#### 1. 계약: `files` 항목에 세 칸 필수 추가 (`contracts/events/raw.notice.collected.v1.json`)
| 칸 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `fileType` | `pdf`, `hwp`, `hwpx`, `xlsx`, `xlsm`, `xls` | 받는 쪽이 파일 형식 판단 |
| `role` | `NOTICE_DOC`(공고문), `UNIT_LIST`(주택목록) | 받는 쪽이 공고문을 찾을 때 |
| `s3Key` | 버킷 안 경로 `raw/{출처}/{글 키}/v{버전}/{순번}-{파일명}`, 또는 `null` | extraction이 우리 S3에서 파일을 가져올 때 |

- `s3Key`는 주소가 아니라 버킷 안 경로예요. 버킷은 비공개라 사용자에게는 지금처럼 `downloadUrl`(기관 링크)을 보여 줘요.
- `s3Key`가 `null`인 경우는 보관 기한이 지나 파일을 지운 뒤 재처리할 때뿐이에요. 새로 수집한 이벤트에는 항상 있어요.
- 세 칸 모두 **필수**예요. LH 수집기는 이 계약에 맞춰 LH 담당이 따로 고쳐요(이 PR에서 `sources/lh`는 건드리지 않음).
- 예시:
  ```json
  {
    "name": "모집공고문.pdf",
    "fileType": "pdf",
    "role": "NOTICE_DOC",
    "s3Key": "raw/dcco/43-24794/v1/00-공고문_2026년_상반기_청년매입임대주택_입주대기자_모집공고_20260610.pdf",
    "downloadUrl": "https://www.dcco.kr/web/board/download.do?…",
    "sha256": "…"
  }
  ```

#### 2. collector가 세 칸 채우기
- DB(`raw_files`)에 이미 있는 역할과 S3 위치, 그리고 파일 이름의 확장자를 이벤트에 넣어요(`SavedFile.as_event_file`, `publisher.build_collected_event`).
- 파일을 S3에 올린 **다음에** 이벤트를 만들기 때문에, `s3Key`는 실제로 올린 경로예요. 받는 쪽이 이벤트를 받을 때 파일은 이미 S3에 있어요.

#### 3. 공고문 고르기 규칙
- 형식 우선순위를 **PDF → HWPX → HWP**로 정했어요. 전에는 HWP와 HWPX가 같은 순위라 첨부 순서로 골랐어요.
- 이름 순위를 형식보다 먼저 봐요: `공고문`·`모집공고` → `입주자모집`·`모집안내`·`공급공고` → 그 밖.
  - 경남 사례: 진짜 공고문 `(붙임1) …입주자모집(제2차) 공고문.hwpx` 대신 PDF라는 이유로 `(붙임3) …입주자모집 관련.pdf`를 골랐어요.
- `모집 공고문 및 신청서류`처럼 공고문과 서식이 한 파일이면 공고문 후보로 둬요. `세대 내 구조`·`구조도`(평면도)는 후보에서 빼요.
  - 부산 사례: 진짜 공고문이 '신청서'라는 단어 때문에 빠지고, 평면도 `세대 내 구조.hwp`를 공고문으로 골랐어요.

#### 4. 실제 수집에서 나온 문제
- **NUL 문자로 저장 실패**: 서울·경기·울산 공고문 PDF에서 뽑은 글자에 NUL(`\x00`)이 섞여 PostgreSQL 저장이 실패했어요(12건 FAILED). 글자를 뽑을 때 지워요.
- **대구 제외**: 대구도시공사 robots.txt가 사이트 전체를 막아서(`Disallow: /`) 마이그레이션 `V202610191200__collector_disable_dudc.sql`로 `sources.enabled = false`로 꺼 뒀어요. 정기 수집(`run`·`run-all`)에서 빠지고, 수집기 코드는 남겨 둬서 기관 허락을 받으면 다시 켜면 돼요.
- **특화시설 운영자 모집**: 인천 `특화시설 운영자 모집공고` 2건이 입주자 모집으로 저장됐어요. `운영자·운영기관 모집·공모·선정`은 입주자 모집이 아닌 글로 분류해요. 제목의 `(운영기관 : ○○)`은 입주자 모집이라 그대로 둬요.
