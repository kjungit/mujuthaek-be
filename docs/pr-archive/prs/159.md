### 설정·스케줄
- api·notification `application-prod.yml`: actuator는 health만(`show-details: never`), `server.forward-headers-strategy: framework`. CORS는 이미 `CORS_ORIGINS`를 써요
- 서버가 09~18시(11/7부터 10~19시)만 켜져 있어서 하루 한 번 작업을 11시대로 옮겼어요
  - api: 마감 D-3·D-1 알림 09:00 → 11:00 (꺼져 있던 날은 켜진 뒤 첫 확인 때 따라잡기, 기존 동작), 혜택 상태 00:05 → 11:00 + 서버가 뜬 뒤 1분에 한 번(따라잡기), 정리 작업 03:30·04:30·04:40 → 11:10~11:40
  - notification: 정리 04:00·04:20 → 11:30·11:20
  - collector: 정책 06:30 → 11:00, 정정 확인 03:00 → 11:30, 파일 정리 04:00 → 11:50, 처음 수집 고르기 07:30 → 12:30, 정책 다시 확인 일 05:00 → 금 13:00(주말에 꺼져 있을 수 있어서), 게시판 평일 9~18시 → 9~19시 매시 5분
  - 스프링 cron·APScheduler는 꺼져 있던 시각의 작업을 따라잡지 않아요(APScheduler는 10분 유예). 그래서 켜져 있는 시간에 두고, 놓치면 안 되는 마감 알림·혜택 상태는 따라잡기가 있어요
- ENV_FILE 이름 확인: 자바는 그대로 읽고, 파이썬은 compose `environment:`에서 `DB_URL`(← COLLECTOR_DB_URL·EXTRACTION_DB_URL)과 `RABBITMQ_URL`(← RABBITMQ_USER·PASSWORD·HOST)로 바꿔 넘겨요. api의 `NOTIFICATION_SERVER_URL`은 compose에서 `http://notification:8081`
