### 무엇을
공공 상가 위치의 **상권 점수** (계획 7단계, 33~37번). 사용자 업종이 있어야 "같은 업종"을 셀 수 있어서 요청 때 계산하고 저장하지 않아요.

`GET /api/v1/areas/commercial/{siteId}?industry=` (API 문서 그대로, 공개 GET):
```json
{ "siteId": "…", "stores300m": 10, "sameIndustry300m": 4, "industryGroup": "CAFE",
  "nearestStation": { "name": "…역", "meters": 600, "walkMinutes": 12 }, "households": null,
  "scores": { "DENSITY": 17, "COMPETITION": 0, "TRANSIT": 79 }, "score": 32,
  "calculatedAt": "2026-10-25T12:00:00+09:00" }
```
- **밀도(DENSITY)**: 300m 안 점포 수
- **경쟁(COMPETITION)**: 입지계수 = (300m 안 같은 업종 ÷ 300m 안 전체) ÷ (전국 같은 업종 ÷ 전국 전체). 1보다 크면 과밀이라 낮게. 같은 업종이 없는 업종이거나 300m 안 점포가 0이면 빠져요
- **교통(TRANSIT)**: 가장 가까운 도시철도역 거리 (KNN 5개 중 타원체 거리 최소 — 세권 지표와 같은 방식)
- **총점**: 있는 항목의 평균, 0.5 올림
- **업종**: `FOOD`·`CAFE`는 상가 업종 묶음, `RETAIL`은 소매 대분류 `G2`, 그 밖은 같은 업종 없음(대소문자 무시)
- siteId는 area 위치 ID. 없는 위치·좌표 없는 위치는 404 `AREA_SITE_NOT_FOUND`

### 사람이 확인할 것
- **점수 구간은 임시 값이에요**: 공공 상가 공고 정답 케이스가 없어서 밀도 `{0,30,100,200}→{0,50,85,100}`, 입지계수 `{0.5,1.0,1.5,2.5}→{100,70,40,0}`, 역 `{300,500,1000,2000}→{100,85,55,0}`으로 넣었어요. 실제 공고 몇 개로 맞춰 보고 새 규칙 버전으로 고쳐야 해요
- **`households`(단지 세대 수)는 늘 null**: 공고 자료라 area가 몰라요(area는 다른 모듈을 안 부름). 화면이 공고 상세에서 가져오거나, notice가 응답을 합쳐야 해요
- 생활권 점수 계산은 `score_weights`의 LIFE 지표만 써서 새 규칙이 기존 점수를 바꾸지 않아요
