### 무엇을
area 저장·조회 방식 비교 도구와, collector `area-upload --skip-upload` 경로의 로컬 MinIO 테스트를 넣어요. (area 적재 스택 6, [#56](56.md) 위에 쌓음)

- `tools/area-bench/`: `run.sh`, SQL 11개, 파이썬 4개, README
  - `run.sh synthetic`: area 마이그레이션만 된 빈 DB에 가짜 자료(상가 277만 줄 규모)를 만들어 비교
  - `run.sh real`: 원천 21개를 실제로 적재한 DB에서 비교. 실제 자료는 바꾸지 않고, `bench` 스키마·종류별 부분 인덱스·`area.stores_part`를 만들었다가 끝에 모두 지워요
  - 재는 것: A. 세권 지표 계산(지표마다 따로 / 단지마다 한 쿼리 / 전체 한 쿼리, 공간 인덱스 하나 vs 종류별 부분 인덱스), B. 목록 API 읽기(조인 한 번 / ID 묶음 두 번 / N+1), C. 상가 시도별 파티션(조회, 서울 다시 넣기)
  - 결과 파일 `results-*.txt`는 `.gitignore`에 넣어 커밋되지 않아요. 파티션 바꿔 끼우기 SQL은 `/tmp` 고정 경로 대신 `mktemp` 임시 파일에 써요
  - 앱 코드가 아니라 CI에서는 돌지 않아요. 파이썬은 ruff 0.17.0 검사·포맷을 통과하게 맞췄어요
- `services/collector/tests/test_area_command.py`: 로컬 MinIO 테스트 1개 (`COLLECTOR_TEST_S3=1`일 때만)
  - 파일을 메타데이터(source·data-date·sha256)와 함께 먼저 올려 두고, 목록(`--manifest … --skip-upload` 경로)으로 이벤트만 기록되는지
  - 목록의 sha256이 S3 메타데이터와 다르면 그 줄을 거절하는지
  - 객체를 다시 올리지 않는지(메타데이터 그대로). 끝나면 올린 객체를 지워요. 기준일을 1999-01-01로 써서 실제 원천 키와 겹치지 않아요

### 왜
- 세권 계산 방식, 부분 인덱스, 목록 API 조인 방식은 다음 단계(세권 계산 PR, REST 목록 PR)에서 실제 쿼리로 다시 재고 정하기로 했어요. 그때 같은 측정을 그대로 다시 돌릴 수 있게 도구를 저장소에 둬요. 측정 결과 자체는 환경(코어 수·메모리)마다 달라서 커밋하지 않아요
- 개발 S3에 이미 올린 원천 21개는 개발 서버에서 `--skip-upload`로 적재할 예정이라, 그 경로를 실제 S3 동작(MinIO)으로 확인해 둬요
