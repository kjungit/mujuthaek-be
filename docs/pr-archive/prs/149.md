### 왜
최상위 관리자(SUPER_ADMIN)는 화면에서 만들 수 없어서([#147](https://github.com/prgrms-be-devcourse/NBE11-13-final-Team02/pull/147)), 배포 뒤 첫 최상위를 정하려면 상용 DB에 직접 update를 해야 했어요.

### 무엇
- `ADMIN_BOOTSTRAP_USER_ID`(application.yml `app.admin.bootstrap-user-id`)에 회원 ID를 넣고 api를 띄우면 그 회원을 최상위로 지정해요 (`SuperAdminBootstrap`, ApplicationRunner)
- 최상위가 이미 있으면 아무것도 안 해요. 값을 그대로 둬도 다시 바뀌지 않고, 그 뒤로는 화면의 넘기기로만 바꿔요
- 없는 회원·이용 정지 중인 회원·ID 형식이 아닌 값은 경고 로그만 남기고 서버는 그대로 떠요
- 일반 관리자였으면 받은 권한 줄은 지워요 (최상위는 전부 가진 것으로 봐요)
- 변경 기록(admin_changes)에 APPOINT · "환경 변수로 처음 최상위 지정" · 바꾼 사람 없음으로 남아요
- 서버 여러 대가 동시에 떠도 최상위 한 명 unique index로 하나만 지정돼요
- 처음 가입한 사람을 자동으로 올리지 않아요 (배포 직후 아무나 먼저 가입하면 최상위가 되니까요)

### 운영 순서
1. 관리자로 쓸 계정으로 소셜 로그인 가입
2. `/api/users/me`의 `id`를 `ADMIN_BOOTSTRAP_USER_ID`에 넣고 api 재시작

### 확인
- `AdminUserServiceTest` 새 테스트 (이미 있으면 건너뜀, 없는 회원·정지 회원 거절, 권한 줄 지움, 기록, 두 번째는 그대로), `ModuleStructureTest` 통과
- 로컬에서 일반 회원 ID를 넣고 api를 띄워 SUPER_ADMIN 지정·변경 기록 확인
