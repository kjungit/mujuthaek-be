### 무엇을
요청 때 계산하는 **생활권 총점과 통근 거리** (계획 5단계, API 문서 `POST /areas/score`의 계산 부분). API(컨트롤러)는 8단계 PR에서 붙여요.

`AreaScoreService.score(위치들, 가중치, 직장 위치|null)` → 위치마다 `SiteScore(siteId, total, categoryScores, commuteMeters, commuteMinutes)`
- **항목 점수**: 저장된 생활권 항목 점수(6단계, 교통·학군·공원·편의·병원)
- **직장**: 직장 위치에서 위치까지 직선거리(PostGIS 타원체 거리)를 점수 규칙 `work_distance_m`(3km 100 → 7km 80 → 15km 60 → 25km 30 → 40km 0, #81에 있던 규칙)으로
- **총점**: Σ(점수 × 가중치) ÷ 가중치 합, 0.5 올림(`TotalScore`). 가중치 0~10(밖이면 거부), 모두 0이면 같은 비중. 직장 위치가 없으면 직장 항목 없이
- 사용자 가중치·직장 위치가 들어가서 **저장·로그 안 함**
- 받은 순서대로, 없는 위치는 빠져요(404로 할지 8단계 API가 정함). 좌표·점수가 없는 위치는 총점 `null`

- API 문서의 `priorities` 키는 소문자(`work`, `transit` …)라 8단계 API에서 `LifeCategory`로 바꿔요

### 테스트
- 규칙: `work_distance_m` 구간 경계(1·3·5·7·25·40·90km), 없는 버전·지표
- 서비스(실제 DB): 같은 비중 (80+60+40+20+0)÷5=40, 가중치(교통만 → 80, 교통3·공원1 → 70), 정확히 5km(`st_project`) → 직장 90·총점 90, 같은 입력 같은 결과, 같은 비중이면 직장도 한 항목 (200+90)÷6 → 48, 없는 위치는 빠지고 좌표 없는 위치는 총점 null, 가중치 11 거부
