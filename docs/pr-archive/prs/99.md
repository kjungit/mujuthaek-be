### 무엇

맞춤 목록(`POST /api/v1/notices/search`)의 정렬에 생활권 총점을 넣었어요. 9단계예요.

- **`RECOMMENDED`(기본)**: 판정 → 마감 임박 → 생활권 총점 → id 순으로 정렬해요.
  - 판정 순서는 지원 가능 → 확인 필요 → 지원 불가예요.
  - 생활권 총점은 높은 순이고, 점수가 없는 공고는 뒤로 가요.
  - 판정과 마감일이 같은 공고끼리만 총점으로 순서가 갈려요.
- **`AREA_SCORE`(새로 추가)**: 생활권 총점 높은 순으로만 정렬해요. 점수가 없는 공고는 맨 뒤예요. 점수가 같으면 id 순이라서 커서로 다음 페이지를 받아도 순서가 바뀌지 않아요.
- `sort`에 허용하는 값에 `AREA_SCORE`를 추가했어요. 다른 값은 지금처럼 400이에요.
- 생활권 총점은 #98에서 목록 항목에 붙인 `areaScore`를 써요. 대표 위치의 생활권 총점이고, 다섯 항목을 같은 비중으로 계산해요. 그래서 새로 읽는 테이블은 없어요.

### 계획 문서와 다른 점

- 계획(48번)에는 `RECOMMENDED`의 마지막 기준이 **관심 지역**이었어요. 그런데 관심 지역을 서버에 저장하는 기능(`/me/interests/housing`)이 아직 user 모듈에 없어요. 그래서 이번에는 넣지 않았어요.
- 관심 지역 저장이 생기면, 로그인 사용자의 관심 지역에 든 공고를 총점 다음 기준으로 앞에 두면 돼요. 이때 호출 방향은 eligibility → user예요.
