### 무엇을
공고 자격 판정 엔진이에요. (REST 스택 5/7, [#50](50.md) 위에 쌓음) 판정 API(`POST /eligibility/notices/{id}/evaluate`)는 이 스택의 7번째 PR에서 붙여요.

- **판정 입력** `eligibility/dto/request/ApplicantRequest` → `eligibility/rule/Applicant`: API 설계 "판정 입력"의 칸 그대로. 모두 비워도 되고, 형식만 검사(생년월일 과거, 시군구 5자리, 금액 0 이상, 코드 값). 연월은 `"2025-04"`. **toString에서 소득·자산·자동차가액·가용 현금·수급 여부·순위 체크·생년월일을 가려요**
- **나이·기간** `rule/Periods`: 기준일의 만 나이, 연월 값(혼인·무주택·청약 가입)은 그 달 1일부터 꽉 찬 개월·년
- **조건 하나** `rule/CriterionJudge`: 판정 틀(`contracts/schemas/housing-judgment.v1.json`)의 조건 12종을 `MET`·`NOT_MET`·`UNKNOWN`으로
  - 나이, 거주지(법정동코드 앞부분 비교), 무주택, 소득(**공고에 인쇄된 가구원 수별 월 상한표**), 총자산·자동차가액(가구원·자녀 수로 바뀌는 상한), 혼인, 자녀, 청약통장, 수급 상태, 택일(ANY_OF), 직접 질문(ASK)
  - `UNKNOWN`: 입력이 비었을 때(`needs`로 넣을 칸), 검수 중(`inReview`), 입력 칸으로 알 수 없는 조건(거주 기간·청약 예치금·부모 소득·장애인 등), 인쇄된 소득표가 없을 때
  - 결과: 조건 ID·종류(`AGE`·`INCOME`·`CAR_VALUE` …)·화면 문구(`나이 · 만 19~39세`, `총자산 · 2억 4,500만 원 이하`)·이유·`needs`·소득 기준(`threshold`)·근거 원문과 쪽. **사용자가 보낸 값은 넣지 않아요**
- **묶기** `rule/Judge`: 공급 대상마다 공통 + 대상 조건이 모두 충족 → `ELIGIBLE`, 불충족 하나 → `INELIGIBLE`, 그 밖 `NEEDS_INPUT` / 공고 전체는 대상 하나라도 `ELIGIBLE`이면 `ELIGIBLE` → 아니면 `NEEDS_INPUT` → `INELIGIBLE`. 조건 수 요약과 `missingInputs`
- **판정 틀 읽기** `eligibility/mapper/JudgmentReader`: `extraction.completed`의 `judgment` JSON → 엔진 모델. 모르는 조건 종류는 직접 질문으로 바꿔서 조용히 지원 가능이 되지 않게 해요

### 왜
- 판정 입력은 `conditions[]`(일반 조건식)와 `judgment`(판정 담당이 정한 판정 틀) 두 가지가 계약에 있는데, 판정 틀이 공급 대상별 묶음·조건 종류·인쇄된 기준표까지 판정용으로 정리돼 있고 API 설계의 응답(`targets[].items[].key`)과 바로 맞아서 판정 틀을 기준으로 했어요.
- `eligibility/rule`은 규칙대로 스프링·JPA 없는 순수 자바예요 (JSON 읽기는 mapper).
- 정해야 할 것 / 다음에 할 것
  - **직접 질문(ASK)의 답**을 받을 칸이 판정 입력에 없어요(설계 문서의 `rankChecks`는 2·3순위용). 지금은 항상 확인 필요예요. `applicant.answers`(조건 ID → YES/NO) 같은 칸을 문서에 더할지 정해야 해요
  - 인쇄된 소득표가 없는 공고는 기준 금액(기준 중위소득 등)이 있어야 판정돼요 → 다음 PR(기준값 테이블)
  - 거주 기간·청약 예치금·막내 자녀 나이·맞벌이·신생아처럼 판정 입력에 칸이 없는 조건은 확인 필요로 둬요
