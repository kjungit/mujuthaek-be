### 무엇을
도로명주소 사전에 아직 없는 **새 건물**의 좌표를 도로명주소 좌표제공 API로 받아요 (3-3). 지금까지는 대표점(대략 위치)으로 갔어요. 실측에서 금천구 시흥대로 377이 이 경우였어요.

흐름(`AddressLocator`): 검색 API로 건물 하나를 고름 → 사전에 없음 → **좌표제공 API**(검색 결과 칸 `admCd`·`rnMgtSn`·`udrtYn`·`buldMnnm`·`buldSlno`) → 출입구 `entX`·`entY`(UTM-K, EPSG:5179) → 경위도 → `OK`, method `COORD_API`(`notice_locations`가 이미 받는 값). 키가 없거나 좌표가 없으면 지금처럼 대표점, API를 못 썼고 대표점도 없으면 `API_ERROR`.

| 커밋 | 내용 |
| --- | --- |
| 좌표제공 API 클라이언트 | `JusoCoordClient`(`AddressCoordinates`), `CoordOutcome`, 설정 `mujuthaek.area.juso-coord`, 키 `JUSO_COORD_API_KEY`(검색 API와 다른 키). 검색 API 클라이언트와 같은 규칙: 키는 POST 폼으로(URL·로그에 안 남게), 시스템 오류·5xx·연결 실패는 2번 다시, 키 오류는 바로, 요청 값 오류는 바로, 하루 한도 |
| UTM-K 좌표를 경위도로 | `PostgresUtmkTransform` — 도로명주소 적재와 같은 `st_transform(5179 → 4326)` |
| 새 건물은 좌표제공 API로 | `AddressLocator`에 넣고 `GeocodeResult.Method.COORD_API` |
