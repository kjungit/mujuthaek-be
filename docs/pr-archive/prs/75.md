1. **저장소 법정동코드표를 리소스로**
   - 원본: `services/extraction/data/legal-dong-codes/legal_dong_20260929.csv` (AI 쪽이 이미 쓰는 파일, UTF-8 쉼표 구분, 53,387줄). 코드표를 둘로 두지 않으려고 옮기지 않고, Gradle `processResources`로 api 리소스 `common/regions/`에 복사해요. 원본이 없으면 빌드가 멈춰요
   - 쉼표·탭, UTF-8·CP949 둘 다 읽어요 (따로 받은 파일 경로 적재는 그대로)
   - 세종: 파일에 시도 줄(3600000000)이 없고 3611000000이 시도 겸 시군구라, 시도 36을 만들어 넣어요
   - 전남광주 통합(12) 짧은 이름
   - #48의 테스트 자료(CP949)는 이 원본과 다른 판이라, 원본에서 그대로 뗀 줄(`common/legal_dong_sample.csv`)로 바꿨어요
2. **예전 법정동코드 → 지금 코드 대응표** — 새 마이그레이션 `common.region_code_changes(old_code, new_code, base_date)`, 코드는 모두 10자리
   - 법정동코드표에는 예전 → 새 칸이 없어서 적재 때 계산해요
   - **이번 개편의 시군구 계보 안에서만** 이어요: 인천 28110 → 28125·28155, 28140 → 28125, 28260 → 28275·28290, 화성 41590 → 41591~41597, 부천 41190~41199 → 41192·41194·41196, 광주 29·전남 46 → 12, 강원 42 → 51, 전북 45 → 52 (시군구 이름이 같은 것)
   - 동·리는 계보의 새 시군구들 안에서 **동 이름이 하나만 맞을 때만**. 계보 밖 폐지 코드는 대응 없음 — 같은 시도 전체로 찾으면 동 이름이 겹치는 곳이 많아(서울 신사동은 은평·강남에 있고 성동·서대문·서초 것은 폐지) 오래전 폐지 코드가 엉뚱하게 이어지기 때문이에요
   - 한 예전 코드가 여러 새 코드로 갈라질 수 있어 칸 하나(`replaced_by`)가 아니라 표예요. 새 코드가 하나로 정해지는 시도·시군구만 `replaced_by`도 채워요 (29 → 12, 28140 → 28125)
   - 화성시·부천시는 시가 그대로라 시군구 줄은 없고 그 아래 동만 일반구로 이어요
3. **이름으로 지역 코드 찾기** — `RegionQueryService.resolve(시도 이름, 시군구 이름)` → 코드 또는 후보들
   - 시도: 정식·짧은 이름·짧은 이름+시/도 (서울특별시·서울·서울시)
   - 시군구: 일반구는 시와 같이(수원시 장안구) 또는 구만(장안구)
   - 같은 이름 구(중구·동구·서구…)는 시도가 있어야 하나로, 없으면 후보로
   - 폐지된 이름은 지금 코드로(광주광역시 동구 → 12210), 갈라진 건 새 시군구들을 후보로(인천 중구 → 28125·28155)
   - `toCurrent(법정동코드 10자리)`: 대응표의 지금 코드, 없으면 그대로 — 공고가 보내는 위치의 법정동코드에 쓸 것
4. **뜰 때 코드표 넣기** — `RegionStartupLoader`: 빌드에 들어간 판이 DB에 넣은 판보다 새로우면 넣고, 같으면 아무것도 안 해요. **여러 인스턴스가 동시에 떠도 한 번만** 넣게 트랜잭션 advisory lock을 잡고 기준일을 다시 본 뒤 넣어요. 끄려면 `mujuthaek.regions.load-on-startup=false`

### 왜
공고 단지 주소를 좌표로 바꿀 때 주소 사전은 시군구 코드로 찾는데, 공고에는 "서울시 마포구", "광주광역시 광산구"처럼 이름만 있어요. 2026 개편(인천 일반구, 화성·부천 일반구, 전남광주 통합, 강원·전북 특별자치도)으로 예전 이름·코드가 섞여 들어오기도 해요.
