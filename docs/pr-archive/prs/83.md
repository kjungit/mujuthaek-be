### 무엇을

좌표 찾기(3단계)의 마지막 검사 — 찾은 좌표가 주소의 시군구·법정동 안에 있는지 — 와 그 경계 자료를 만들어요 (area 3-4). 원천부터 적재·검사까지 한 PR이에요.

#### 원천: 구역의 도형 (2026-09-30)
- 시도 zip 16개, 시도 코드 폴더 안 층 7개 중 **시군구 `TL_SCCO_SIG`·법정읍면동 `TL_SCCO_EMD` 둘만** 써요
- `.prj`(좌표계 파일)가 없지만 **UTM-K(EPSG:5179)** 로 확인: 청운동 경계 첫 점(953700.0, 1954605.1) → 북위 37.58968, 동경 126.97556
- 시군구 256개(점 1,346,677), 법정읍면동 5,067개(점 3,536,648). EMD 코드는 **8자리**(시군구 5 + 읍면동 3) — 법정동코드 10자리와 앞 8자리로 비교(끝 두 자리는 리)

#### collector
- `area/boundary_csv.py`: SIG·EMD 층을 시도 16개에서 모아 전국 CSV 2개(`boundary_sig.csv`, `boundary_emd.csv`, 칸 `code,name,wkt`, 좌표는 UTM-K 그대로). 여러 조각·구멍은 GeoJSON 규칙대로, 잘못된 도형은 `make_valid`. 코드 자릿수·중복·시도 16개 검사. pyshp·shapely는 `boundary` 의존성 묶음에만
  ```
  uv run --group boundary python -m mujuthaek_collector.area.boundary_csv <juso_boundary 폴더> <출력 폴더>
  ```
  실제 SHP 16개로 돌려 보니 **개발 S3에 올라가 있는 두 파일과 sha256까지 같아요**(시군구 256개·고친 도형 8개 47MB, 법정읍면동 5,067개·고친 도형 31개 123MB). pyshp가 "반시계 고리만 있는 도형" 경고를 40개쯤 내는데, 그 고리를 바깥 고리로 읽어서 올라간 파일과 같은 결과예요
- 원천 `REGION_BOUNDARY_SIG`·`REGION_BOUNDARY_EMD`(범위 `ALL`, `area/{원천}/{기준일}/boundary_sig.csv`·`boundary_emd.csv`)
- `area/area_manifest_boundary.csv`: 개발 S3에 이미 올린 CSV 2개 + 원본 zip 16개(`REGION_BOUNDARY_RAW`). 원본 zip 줄은 보관만이라 적재 요청을 만들지 않고 세기만 해요

#### 계약
`area.source.ready`의 source에 두 원천 추가, s3Key 파일 이름은 원천마다 `boundary_sig.csv`/`boundary_emd.csv`로 고정. 예시 `area.source.ready.boundary.json`(실제 값). collector의 키 규칙 테스트가 계약 파일의 패턴을 직접 읽게 바꿨어요(복사한 패턴이 계약과 어긋나지 않게).

#### api
- 테이블 `area.region_boundaries(level SIG·EMD, code, name, geom geography(MultiPolygon), data_date)` + 공간 인덱스 (`V202610241900`)
- 함수 `area.boundary_from_utmk_wkt(wkt)`: `st_multi(st_collectionextract(st_makevalid(st_transform(st_geomfromtext(wkt, 5179), 4326)), 3))`. 읽을 수 없거나 면이 남지 않으면 null → 그 줄만 `BAD_GEOMETRY`로 거절(파일 전체를 실패시키지 않게)
- 적재기: 기존 흐름(stage_raw → stage_norm → 공통 검사 → 반영) 그대로. 코드 자릿수 `BAD_CODE`, 공통 검사가 한국 범위를 보도록 도형 안의 한 점을 위도·경도로 넣어서 좌표계를 잘못 알면 `OUT_OF_RANGE`로 걸려요. 이름·도형이 바뀐 줄만 고치고, 지우기·줄어듦 검사는 같은 단계(SIG·EMD) 안에서만
- 경계 검사 `PostgresRegionBoundaryCheck.check(시군구 코드, 법정동코드|null, 위도, 경도)` → `BoundaryCheck`:
  - 시군구: 경계 안 또는 **50m 이내**(`st_dwithin(geom, 점, 50)`)면 통과 — 건물 출입구가 경계를 몇 m 넘는 경우를 실패로 만들지 않으려고. 밖이면 `OUT_OF_REGION`
  - 법정동: 앞 8자리 경계에서 50m 넘게 밖이면 **실패가 아니라** `emdMismatch`(→ `region_mismatch`)만
  - 그 시군구 경계 자료가 없으면 `NO_BOUNDARY`로 통과(경계를 아직 적재하지 않은 환경)
  - 도로명주소 원천에서 좌표가 동쪽으로 밀린 34줄은 시군구 검사로 걸려요 (사전 적재 때는 표시하지 않음)

### 테스트
- collector: 시험 SHP(사각형·구멍·두 조각·꼬인 고리)로 CSV, 코드 자릿수·중복·시도 수 오류, 경계 목록이 키 규칙대로이고 원본 zip 16줄은 건너뜀, 이벤트가 계약에 맞고 파일 이름이 다르면 거절
- api 적재: UTM-K → 경위도(청운동 근처 37.59, 126.97), 꼬인 고리는 고쳐서 두 조각, BAD_CODE·BAD_GEOMETRY, 다시 넣으면 그대로(unchanged), 법정읍면동 적재가 시군구를 지우지 않음
- 경계 검사(시험 도형): 안 / 구멍 안(어느 구역도 아님) / 구멍 밖 / 둘째 조각 / 밖 30m(50m 여유로 통과) / 밖 100m(실패), 법정동 밖은 표시만, 경계 자료 없음
