### 무엇을
계획 8단계의 **area 쪽 조회 API** (44·45·47번). 공고 목록·상세·지도에 area 값을 붙이는 notice 쪽(46번)은 다음 PR로 나눴어요(리뷰하기 쉽게).

| API | 내용 | 캐시 |
| --- | --- | --- |
| `GET /api/v1/areas/sites/{siteId}` | 좌표, 대략 위치 여부, 세권 지표(가장 가까운 역 이름·거리·도보 분, 반경별 수), 생활권 항목 점수, 세권 태그, 계산 시각 | — (공개) |
| `POST /api/v1/areas/score` | `siteIds`(1~50)·`priorities`(`work`·`transit`·`school`·`park`·`convenience`·`hospital`, 0~10)·`workplace`(`label`·`lat`·`lng`)로 위치마다 총점·항목 점수·통근 거리(5단계 서비스) | `no-store` (판정 API와 같게, 저장·로그 없음) |
| `GET /api/v1/areas/criteria` | 규칙 버전, 지표별 점수 구간, 생활권 항목의 지표 비중, **데이터 출처**(47번) | 하루 공개 캐시 |

- siteId는 area 위치 ID(uuid, 팀 결정). 없는 위치·좌표 못 찾은 위치는 404 `AREA_SITE_NOT_FOUND`
- `POST /areas/score`의 `items`는 받은 순서이고, 없는 위치는 빠져요. 가중치가 모두 0·없음이면 같은 비중
- 잘못된 요청(빈 siteIds, 가중치 11, 위도 91 …)은 400 `VALIDATION_FAILED`

### API 문서와 다른 점 / 사람이 확인할 것
- **지표 이름**: 문서 예시의 `elementarySchools1km`·`parks1km`·`hospitals1km`·`pharmacies1km`는 저장하는 지표가 아니라서 없어요. 실제 지표 14개를 같은 이름 규칙으로 내보내요: `nearestStation{name, meters, walkMinutes}`, `stationCount1km`, `busStopNearestM`, `busStops300m`, `elementaryNearestM`, `middleSchools1km`, `highSchools1km`, `parkNearestM`, `parkArea1kmM2`, `hospitalNearestM`(2차 이상 병원), `clinics500m`, `convenienceStores300m`, `martNearestM`, `stores300m`. 근처에 없는 거리는 `null`, 개수는 0
- **태그**: 문서 예시의 `FOREST`가 아니라 코드표대로 `PARK`예요 (`STATION`·`SCHOOL`·`ELEMENTARY_NEAR`·`PARK`·`CONVENIENCE`·`CLINIC`)
- **`approximate`**: 문서에 없는 칸을 더했어요 — 법정동 대표점(대략 위치)이면 true라 화면이 "대략 위치"를 표시할 수 있어요
- **데이터 출처 문구**: 계획은 "출처 문서의 문구 그대로"였는데 그런 문서가 없어서 원천 파일 이름의 데이터·기관만 넣었어요. 이용 조건은 병원(건강보험심사평가원, 공공누리 제1유형 + 링크)만 확인됨 — **나머지 기관 약관과 표기 문구는 사람이 확인 필요**
- **로그인 사용자의 저장된 가중치 채우기**(문서: 로그인이면 빈 `priorities`를 서버가 채움)는 안 했어요 — 사용자 설정(`/me/preferences`)이 아직 없고, area는 user 모듈을 부르지 않아요. user/notice 쪽에서 채워 넘기는 방식이 필요
- `/areas/regions/{regionCode}`·`/areas/compare`(동네 비교)는 동네 지표 설계가 없어 이번 범위 밖이에요
