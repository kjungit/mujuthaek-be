### 왜
판정·점수 계산(세권, 생활권·상권 점수)이 쓸 기초 데이터가 api에 먼저 있어야 해요. 원천 파일 21개(지하철·버스·학교·공원·병원 각 1개, 상가 시도 16개)는 2026-10-22에 S3 `area/`에 올려 두었고, 이 PR은 그 파일을 테이블로 옮기는 부분이에요.

설계상 정한 것:
- **트랜잭션**: 데이터 변경은 트랜잭션 하나라 실패하면 이전 데이터가 그대로 남아요. 실행 기록은 실패해도 남아야 해서 적재기가 커넥션을 직접 잡고 커밋·롤백해요. 부르는 쪽에 `@Transactional`을 붙이지 않아요.
- **`@Component`인 이유**: `@Repository`는 예외 변환 프록시(CGLIB)를 만들어 `final` 클래스면 앱이 안 떠요. 예외 변환이 필요 없어서 `@Component`예요.
- **마이그레이션**: PostGIS는 DB를 만들 때 관리자 계정으로 설치하고(`infra/db/init/01-databases.sh`), `area` 스키마는 Flyway가 만들어서 두 줄은 넣지 않았어요. **RDS에는 배포 전에 관리자 계정으로 `create extension postgis`가 필요해요.**
- **PostgreSQL 드라이버**를 `runtimeOnly` → `implementation`으로 바꿨어요 (COPY용 `CopyManager`를 직접 씀).
- **테스트 자료**: `.gitignore`의 `*.csv`(비밀값용)에서 area 자료 폴더만 예외로 열었어요. CP949 인코딩과 끝의 빈 줄(빈 줄 건너뛰기 검사용)을 지키려고 editorconfig 규칙과 git 줄바꿈 변환을 껐고, sha256 고정 테스트로 바뀌면 실패하게 했어요. 한글 파일 이름은 LANG이 없는 CI·Docker에서 열리지 않아 영문(`stores_gangwon.csv` 등)으로 했어요.
