### 왜
운영 서버 성능 테스트(동시 사용자 100명 목표, 스트레스·한계 찾기 등)에서 **서버 안에서 잰 API별 p95·p99**와 JVM·DB 커넥션 상태를 같이 보려고 해요. 지금은 actuator가 health만 열려 있어 서버 쪽 숫자를 볼 수 없어요. k6(사용자 쪽) 숫자와 서버 숫자를 같이 봐야 느린 원인이 네트워크인지 서버·DB인지 나눌 수 있어요.

### 바꾼 것
- api·notification에 `micrometer-registry-prometheus` 추가 → `/actuator/prometheus`
- 운영 노출: `health` → `health,prometheus`
- `management.metrics.distribution.percentiles-histogram.http.server.requests: true` → Prometheus에서 `histogram_quantile(0.95, …)`로 API(uri)별 p95·p99
- Hikari(`hikaricp_connections_active/pending`), JVM 힙·GC 지표도 같이 나와요

### 밖에서 못 읽어요
- nginx가 `/actuator/health` 말고 `/actuator/*`는 404 (nginx 설정 변경 없음)
- api·notification 포트는 호스트 `127.0.0.1`에만 묶여 있어 SSH 터널로만 읽어요

### 확인
- `PrometheusEndpointTest`: 요청 뒤 `/actuator/prometheus`에 `http_server_requests_seconds_bucket`, `hikaricp_connections_pending`, `jvm_memory_used_bytes`가 나와요
- api·notification `spotlessApply check` 통과
- 배포 후: `curl http://<EIP>/actuator/prometheus` → 404, 서버 안 `curl 127.0.0.1:8080/actuator/prometheus` → 200
