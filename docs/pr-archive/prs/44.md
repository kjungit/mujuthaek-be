### 무엇을
S3 `area/` 경로의 원천 파일을 열어 적재기에 넘기는 서비스와, 기초 데이터가 바뀌었음을 알리는 이벤트예요. (area 적재 스택 2/4, [#43](43.md) 위에 쌓음)

- `common/config/S3Config`·`S3Properties`: S3 클라이언트. collector와 같은 규칙
  - `S3_ENDPOINT`가 있으면 그 주소(로컬 MinIO)에 경로 방식 주소 + `MINIO_ROOT_USER`·`MINIO_ROOT_PASSWORD`
  - `S3_ENDPOINT`를 빈 값으로 주면 AWS S3 + 기본 인증(EC2 역할 등)
  - `S3_BUCKET`(기본 `mujuthaek-raw`), `AWS_REGION`(기본 `ap-northeast-2`). AWS SDK는 BOM `2.55.9`
- `area/repository/S3AreaFileStore`: `area/` 경로만 스트림으로 읽어요 (그 밖이나 `..`이 든 키는 거절)
- `area/service/AreaSourceLoadService.load(Command)`: S3에서 열어 적재기로 넘기고 결과를 로그로 남겨요
  - 파일 문제(칸 없음, 잘린 파일)는 `FAILED` 결과로 돌려줘요 → 다시 해도 같으니 받는 쪽이 재시도하지 않게
  - S3·DB 연결 문제는 예외 → 받는 쪽이 재시도할 수 있게
- `area/event/AreaBaseDataLoaded(source, scope, runId)`: 성공하고 넣거나 바꾸거나 지운 줄이 있을 때만 발행. 세권·점수 다시 계산이 받을 이벤트

### 왜
- 원천 파일은 collector가 S3에 올리고(다음 PR들), api는 그걸 읽어 적재해요. 상가 시도 파일은 수십 MB라 메모리에 올리지 않고 스트림으로 COPY해요.
- **트랜잭션**: 적재기가 커넥션을 직접 잡고 커밋·롤백해서(실패해도 실행 기록을 남기려고) 서비스에 `@Transactional`을 붙이지 않아요. 그런데 트랜잭션 없이 이벤트를 내면 `@TransactionalEventListener`·`@ApplicationModuleListener` 리스너가 아예 불리지 않아서, **발행만 `TransactionTemplate`의 짧은 트랜잭션 안에서** 해요.
