### 무엇을
area 원천에 **도로명주소 출입구 정보**(주소기반산업지원서비스 전체분)를 추가해서, 도로명주소 → 좌표 사전 `area.address_points`를 채워요. (area 적재 스택 7, dev 위)

- **테이블** `area.address_points` (새 마이그레이션 `V202610241730__area_address_points.sql`): 도로명주소 하나에 좌표 한 줄
  - 원천 고유 키 `address_id`(도로명주소관리번호 26자리)가 **기본 키**예요. 팀 규칙(UUID v7)의 예외로, 전국 약 642만 줄이라 공간을 아끼고 다른 테이블이 이 줄을 참조하지 않는 사전 테이블이기 때문이에요
  - 인덱스는 공고 주소를 찾을 때 쓰는 `(sigungu_code, road_name, underground, bldg_main, bldg_sub)`와 지우기 범위 `load_scope`만 둬요. 공고 주소에는 도로명코드가 없어서 도로명코드 인덱스는 두지 않아요
- **원천 정의**: `AreaSource`에 구분자·머리줄 없음·범위 필수(`delimiter()`, `headerless()`, `scoped()`)를 두고 `ADDRESS_ENTRANCE`를 추가했어요 (머리줄 없는 `|` 구분 19칸, CP949, 칸 이름 `c1`~`c19`)
- **적재기**
  - 머리줄이 없으면 머리줄을 읽지 않고 고정 칸 이름을 써요
  - `|` 구분이면 COPY의 따옴표 문자를 쓰이지 않는 `\x01`로 바꿔 값 안의 `"`를 그대로 둬요. 빈 줄 건너뛰기도 따옴표를 세지 않아요(세면 값 안의 `"` 하나 뒤로 끝의 빈 줄을 못 지워요)
  - 좌표 UTM-K(EPSG:5179)는 변환 SQL에서 경위도로 바꾸고, 그다음은 공통 검사(좌표 없음·범위 밖·키 중복) 그대로예요. 번호가 숫자가 아니면 `BAD_NUMBER`로 거름
  - 줄어듦 검사·지우기·반영을 적재 대상별 `switch`로. **지우기를 반영보다 먼저** 해요(경기 주소 약 100만 줄 첫 적재가 상가 때처럼 지우기에서 멈추지 않게, #56과 같은 이유)
  - "바뀐 줄" 비교에 읍면동 이름도 넣었어요 (빠지면 읍면동 이름만 바뀐 줄이 갱신되지 않아요)
  - 지하여부는 0~3을 원천 코드 그대로 받아요. 처음엔 0·1만 받아서 경남 통영 섬 지역(산양일주로·욕지일주로 등) 실제 주소 52줄이 버려졌어요(전국에서 0·1 밖은 이 `3`뿐). 주소 글자의 "지하"는 1일 때만 붙이고, 칸 설명은 새 마이그레이션 `V202610241731__area_address_underground_comment.sql`로 남겨요
- **계약** `area.source.ready` v1 (값 추가만)
  - `source`에 `ADDRESS_ENTRANCE`
  - `scope`: 상가는 시도 이름, **도로명주소는 시도 코드 두 자리**(11, 12, 36 …), 나머지 ALL
  - `s3Key`: 도로명주소는 원본 그대로 `area/ADDRESS_ENTRANCE/{기준일}/address_entrance_{파일 시도코드}.txt`, 나머지는 `.csv`
  - 예시 `area.source.ready.address.json` (실제로 올린 세종 파일 값)
- **collector**: `area-upload --source ADDRESS_ENTRANCE --scope 36110 --data-date 2026-09-30 --file RNENTDATA_2610_36110.txt`
  - 범위는 시도 코드 두 자리, 원본 파일 이름의 다섯 자리 코드도 받아요. 16개 코드 표(12는 전남광주 통합특별시 새 코드, 세종만 36110)
  - txt는 바꾸지 않고 그대로 올려요. 머리줄이 없어서 줄 수에서 머리줄을 빼지 않아요
- **S3 목록** `services/collector/area/area_manifest_address.csv`: 개발 S3에 올린 16개(기준일 2026-09-30)의 원천·범위·키·sha256·원본 이름·줄 수

### 왜
공고에는 주소 글자만 있어서 세권·점수·통근·지도를 하려면 공고 주소를 좌표로 바꿔야 해요. 외부 API로 그때그때 바꾸는 대신 파일 사전을 우리 DB에 두는 이유:
- VWorld 지오코딩은 결과 저장이 금지예요
- 카카오 로컬은 운영 정책상 결과 캐시·복제가 제한돼요
- 도로명주소 API는 호출 한도가 있어요

원천은 주소 하나에 한 줄(대표 출입구)이고 지번이 없어요. 지번 주소 공고는 다음 단계에서 따로 다뤄요.

### 개발 서버 적재 (머지 뒤)
원천 16개는 이미 개발 S3에 올려 두었어요(메타데이터 `source`·`data-date`·`sha256`). RDS·EC2 연결 뒤 개발 서버에서:
```bash
python -m mujuthaek_collector area-upload --manifest area/area_manifest_address.csv --skip-upload
```

#### ⚠️ 마이그레이션 순서 (팀과 정하기)
저장소에는 Flyway out-of-order 설정이 없어요. 머지 직전에 마이그레이션 시각을 dev 맨 뒤(`V202610241721`) 뒤로 다시 매겼어요(`V202610241730`·`V202610241731`).

### 이번에 안 하는 것
공고 주소를 정리·판별해서 이 사전에서 찾는 일(다음 단계 본체), 지번 대응, 경계 안 검사.
