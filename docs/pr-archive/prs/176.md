### 문제 (운영에서 재현)
구로구 도전숙 입주자 추가 모집 공고에서, 부산에 사는 66세 세대원이 소득 40%·자산·자동차 기준만 맞으면 **공고 전체가 「지원 가능」**으로 나왔어요.

- 판정 틀의 대상군이 `청년창업인`, `1인 창조기업인`, `예비창업인`, `(예비)사회적기업인`에 더해 **`월평균소득 50% 이하 및 자산·자동차 기준 충족`**, **`월평균소득 50% 초과 ~100% 이하`**까지 6개였어요.
- 나이·거주·무주택 조건은 `청년창업인` 대상군에만 붙었어요. 소득 구간 대상군에는 소득·자산·자동차 조건만 있었어요.
- 판정은 「대상군 하나라도 지원 가능이면 공고 지원 가능」이에요. 그래서 소득 구간 대상군 하나로 공고 전체가 지원 가능이 됐어요.
- 원인은 추출 프롬프트 규칙이에요. 「순위·계층마다 소득 기준이 다르면 `targetGroups`에 그 이름」이라고만 하고, 모든 신청자에게 같은 조건은 대상 표시를 비우라는 규칙이 없었어요.

### 고친 것
소득 구간은 대상이 아니라 **대상이 갖춰야 할 소득 기준 중 하나**로 봐요.

- **구간 대상군**
  - 이름이 소득 구간이에요(`소득 … N%`).
  - 순위가 없어요.
  - 조건이 소득·자산·자동차뿐이에요(가구원 수 예외 ANY_OF 안의 질문은 괜찮아요).
- **처리**
  - 순위가 없는 대상 대상군마다 「구간 중 하나」(ANY_OF, 구간이 하나면 그 조건 그대로) 조건을 더해요.
  - 구간 대상군은 없애요.
  - 「1순위 …」「2순위」처럼 순위로만 나뉜 공고(대상 대상군 없음)는 그대로 둬요. 기존 테스트 `test_rank_items_become_their_own_groups…`도 그대로 통과해요.

같은 규칙을 두 곳에 넣었어요.
- **api `JudgmentReader` → `IncomeTiers.fold`**: 이미 저장된 공고도 **배포하면 바로** 고쳐져요. 다시 추출하지 않아도 돼요. 공고 판정·맞춤 목록·홈 요약이 모두 이 리더를 거쳐요.
- **extraction `judgment/frame.py` `_fold_income_tiers`**: 새 공고는 판정 틀부터 접혀서 와요.
- **주거 추출 프롬프트 v30**(v29는 롤백용으로 남기고 v28은 삭제): 모든 신청자에게 같은 조건(나이·거주지·무주택·국적·사업자 형태)은 `scope.targetGroups`를 비워요.

### 확인
- api `./gradlew check` 통과. `IncomeTiersTest`로 확인한 것:
  - 도전숙 모양 접기
  - **66세·부산·소득 40% → 지원 불가**
  - 26세·소득 40% → 지원 가능
  - 순위 대상군은 그대로
  - 구간 하나는 일반 조건으로
  - 순위 읽기가 추출과 같음
- extraction pytest 976개 통과. 새 테스트 2개: 접기, 구간 하나
- 계약 파일은 바꾸지 않았어요. ANY_OF는 이미 있는 조건 종류예요.
