### 왜
- 공식 MinIO 이미지를 Docker Hub와 quay.io 모두에서 받을 수 없어요.
  - 대안 중 Chainguard는 `latest`만 있어서 버전 고정이 안 돼요.
  - RustFS·SeaweedFS는 MinIO가 아니라 설정 방식이 달라요.
  - bitnamilegacy는 MinIO 그대로이고 버전을 고정할 수 있어요. 보관용 저장소라 로컬 개발용으로만 쓰고, 운영은 AWS S3예요.
- collector가 로컬에서 S3(MinIO)와 Flyway 마이그레이션을 쓰는데 실행 방법이 없었어요.
- collector의 실제 DB 테스트(`test_storage_postgres`)는 `collector_test` DB가 필요한데, 손으로 만들어야 했어요. init 스크립트는 볼륨이 빌 때만 돌아서, 기존 볼륨용으로 make 명령도 뒀어요.

### 주의
- 이 MinIO 버전부터 커뮤니티판에 **웹 콘솔이 없어요**. 그래서 9001 포트를 뺐어요.
  - 파일 확인: `docker compose -f infra/docker-compose.yml --env-file infra/.env exec minio mc ls --recursive local/mujuthaek-raw/`
- 이미 `minio-data` 볼륨이 있으면 버킷을 다시 만들지 않아요. 초기화하려면 `make clean`을 써요.
- **이 PR 전에 `infra/.env`를 만들었다면 MinIO 값을 바꿔야 해요.** `make infra`는 `.env`가 없을 때만 example을 복사해서, 기존 파일은 그대로 남아요.
  - 옛 값 `MINIO_ROOT_USER=mujuthaek`는 collector 기본값(`minio`)과 달라서 S3 업로드가 인증 실패해요.
  - `S3_BUCKET`이 없으면 `MINIO_DEFAULT_BUCKETS`가 비어서 버킷이 안 만들어져요.
  - `.env`의 MinIO 부분을 `.env.example`대로 고치거나, `.env`를 지우고 `make infra`를 다시 실행해요.
- **옛 MinIO 볼륨이 남아 있으면 MinIO가 뜨지 않을 수 있어요.** 옛 이미지(`minio/minio`)는 root로 돌아서 볼륨 파일 주인이 root인데, bitnami 이미지는 일반 사용자로 돌아요. 권한 오류가 나면 `make clean` 후 `make infra`로 다시 띄워요. DB와 버킷 데이터도 같이 지워져요.
