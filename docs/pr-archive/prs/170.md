### 왜
프론트 「내 정보」·관심 등록·제보를 실제 API에 붙이면서 모자란 백엔드를 채워요 (프론트 PR kjungit/mujuthaek-fe feat/me-real-api).
- 관심 목록 응답이 ID뿐이라 목록에 제목·마감일을 그릴 수 없었어요
- 「내 제보」 목록과, 공고에 묶이지 않은 일반 제보(빠진 공고·화면 오류)가 없었어요
- 사업공간 모집·혜택 화면의 「정보가 틀렸어요」는 보낼 곳이 맞지 않았어요 (사업공간 모집 404, 혜택은 원본 정책 ID만 받음)

### 무엇
- `GET /api/users/me/favorites`: `{…, title, organization, status, applyStart, applyEnd, linkPath}` 추가. 사라진 대상은 title null
- `ScreenPaths`(common): 화면 주소 규칙을 알림·관심 목록·내 제보가 같이 써요 (알림 쪽 규칙을 옮긴 것, 동작 같음)
- 일반 제보 `POST /api/v1/reports` `{field: MISSING_NOTICE·WRONG_INFO·APP_ERROR·ETC, note, screen?, currentValue?}`
  - `notice.notice_reports`에 대상 없이 저장 (마이그레이션: 대상 하나 → 0~1개). 관리자 제보 목록에 `targetType: GENERAL`, 같은 종류끼리 묶지 않아요(묶음 처리 때 남의 제보가 같이 끝나지 않게), 「고치기」 없음
  - 답은 알림함에만 (`REPORT_ANSWERED`, target null, `/me?tab=reports`). 알림 서버 요청은 대상이 있어야 해서 푸시·메일은 보내지 않아요 (마이그레이션: 알림함 대상 칸 null 허용)
- 내 제보 `GET /api/users/me/reports`: 공고·혜택·사업·생활권·일반 제보를 합쳐 최근 100건 (상태·결과·답·화면 주소). notice·area의 공개 조회 서비스를 통해 모아요 (모듈 경계 그대로)
- 사업 제보(`/api/v1/programs/{id}/reports`)가 사업공간 모집도 받고, 내 제보·답변 알림은 사업공간 상세로 가요
- 혜택 제보(`/api/v1/benefits/{id}/reports`)가 혜택 ID도 받아요 (혜택 화면이 쓰는 ID → 정책 원본 ID)
- OpenAPI(notice.v1.json)·README 갱신
