### 무엇을
공고 주소 글자 하나를 좌표 결과 하나로 바꾸는 `AddressLocator`예요 (3-2 마무리). #82에서 검색 API **부품**(클라이언트·검색어 거르기·후보 고르기·호출 수 제한)만 들어가고 그걸 쓰는 곳이 없었는데, 이번에 사전 찾기([#90](90.md))·주소 정리([#74](74.md))·지역 코드([#75](75.md))·경계([#83](83.md))와 이어요.

#### 찾는 순서 (`AddressLocator.locate(주소, 법정동코드)`)
1. 주소 정리 (`AddressParser`)
2. 시군구: 받은 법정동코드(2026 개편 전 코드는 `toCurrent`로 지금 코드) 앞 5자리, 없으면 주소의 시도·시군구 이름(`RegionQueryService.resolve`)
3. 도로명 주소면 사전 → `OK` `FILE`/`FUZZY`
4. 못 찾았거나 지번이면 검색 API → 결과 하나를 고르고(`JusoCandidates`) 그 도로명·번호로 **사전에서 다시 정확히** → `OK` `SEARCH_API`
   - 지하 여부 0·1로 없으면 지하 여부를 빼고 한 번 더 (사전의 섬 주소 코드 `3`, 경남 통영 52줄)
5. 그래도 없으면 법정동 대표점(읍면동 경계의 `st_pointonsurface`) → `APPROX` `CENTROID`:
   받은 법정동코드 → 검색 API가 고른 결과의 법정동 → 주소의 법정동 이름(시군구 안에서 이름이 같은 하나, 리는 앞의 읍·면)
6. 실패: 주소 없음 `PARSE_FAILED`, 검색 API를 못 썼고(한도·장애·키 오류) 대표점도 없음 `API_ERROR`, 나머지 `NOT_FOUND`
   - 검색 API 키가 없는 환경은 그 단계를 건너뛰어요(오류 아님)

결과 `GeocodeResult`(status·method·좌표·찾은 법정동코드·시군구·주소 ID·실패 이유)는 `area.notice_locations`의 `status`·`method`·`fail_reason`·`bjd_code_found` 값과 같아서 3-5가 그대로 저장해요.
