### 무엇을
연도별 판정 기준값과 그걸 쓰는 API 2개예요. (REST 스택 6/7, [#51](51.md) 위에 쌓음) 판정 API는 모두 `/api/v1/eligibility` 아래예요(판정 경로 B).

| 메서드 | 경로 | 하는 일 |
| --- | --- | --- |
| GET | `/api/v1/eligibility/criteria?year=&noticeType=` | 판정 기준 금액 (기준 중위소득, 순위 요건). 하루 캐시 |
| POST | `/api/v1/eligibility/subscription-score` | 청약 가점. `Cache-Control: no-store`, 저장 안 함 |

- **기준값 테이블** `eligibility.criteria_sets` (`V202610220335`): (종류, 연도)마다 쓰기 시작하는 날·값(jsonb)·근거·고친 사람. 종류는 `MEDIAN_INCOME`(기준 중위소득 월액), `URBAN_WORKER_INCOME`(도시근로자 월평균소득), `RANK_CRITERIA`(순위 요건)
- **GET /criteria**: `{ year, validFrom, medianIncomeMonthlyWon: { "1": …, "2": … }, rankCriteria: [{ rank, rule, items }] }`. `year`를 비우면 오늘 쓰는 가장 최근 연도, `noticeType`을 주면 그 유형의 순위 요건(`byNoticeType`에 있을 때). 그해 값이 없으면 404 `CRITERIA_NOT_FOUND`
- **청약 가점** (`eligibility/rule/SubscriptionScore`, 순수 자바)
  - 무주택 기간(최대 32): 만 30세부터, 그 전에 혼인했으면 혼인신고일부터(무주택 시작이 더 늦으면 그때부터). 1년 미만 2점, 1년마다 +2점. 집이 있으면 0점
  - 부양가족(최대 35): 0명 5점, 1명마다 +5점
  - 청약통장 가입 기간(최대 17): 6개월 미만 1점, 1년 미만 2점, 1년마다 +1점
  - 응답 `{ total, max(84), items: [{ key, points, max, reason }], missingInputs }`. 입력이 빈 항목은 `points: null`과 이유
  - 요청은 다른 판정 API와 같은 `{ applicant, referenceDate }` (기준일을 비우면 오늘)
- **판정에 연결**: 판정 틀의 소득 조건에 인쇄된 상한표가 없으면 그해 기준 소득 월액 × 비율(가산 포함, 원 단위 버림)로 상한을 계산해요 (`IncomeBenchmarks`, `CriteriaService.benchmarks`)

### 왜
- 기준 중위소득·순위 요건 금액은 해마다 바뀌어서 코드에 두지 않고 연도별로 둬요.
- **실제 금액은 아직 안 넣었어요.** 설계 문서대로 그해 고시·공고를 보고 관리자가 넣는 값이라, 마이그레이션에 금액을 박지 않았어요. 관리자 기준값 화면(`PUT /admin/criteria/{kind}`)은 관리자 API 차례에 만들고, 그 전에는 SQL로 넣어야 해요:
  ```sql
  insert into eligibility.criteria_sets (kind, year, valid_from, data, source)
  values ('MEDIAN_INCOME', 2026, '2026-01-01', '{"monthlyWon": {"1": …, "2": …}}', '보건복지부 고시 …');
  ```
  값이 없는 동안 `GET /criteria`는 404이고, 인쇄된 소득표가 없는 공고의 소득 조건은 확인 필요로 나와요.
- 청약 가점 요청 모양: 설계 문서는 필요한 칸만 나열해서, 다른 판정 API와 같게 `applicant` 안에 받았어요. 다르게 하자면 바꿀게요.
