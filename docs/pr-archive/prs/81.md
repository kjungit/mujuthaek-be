### 무엇을

공고 위치마다 생활권 항목 점수 5개(교통·학군·공원·편의·병원, 0~100)를 저장된 세권 지표로 계산해 저장하고(area 6단계), 요청 때 쓰는 총점 계산을 만들어요.

#### 테이블과 규칙 (`V202610241852`)
- `area.location_scores(location_id, score_kind LIFE·COMMERCIAL, category, score, score_version)` — 위치가 지워지면 같이 지워짐
- `area.score_rules(score_version, metric, xs[], ys[])`: 지표 하나를 점(xs, ys) 직선 잇기로 0~100, 양끝 밖은 끝 값. 함수 `area.piecewise()`
- `area.score_weights`: 항목 점수 = 지표 점수 가중 합 (항목마다 합 1)
- 규칙 `2026.1` = 설계 초안 숫자 그대로

| 항목 | 지표 (가중치) | 구간 |
| --- | --- | --- |
| TRANSIT | 역 거리 0.7, 300m 안 버스정류장 0.3 | 역 500m 100 → 1km 70 → 2km 40 → 3km 0 / 정류장 0곳 0 → 5곳 100 |
| SCHOOL | 초등 거리 0.6, 1km 안 중 0.2, 고 0.2 | 300m 100 → 600m 80 → 1km 60 → 2km 0 / 0곳 0 → 2곳 100 |

구간을 고치면 이 V 파일을 고치지 않고 새 마이그레이션으로 새 버전(`2026.2` …)을 넣어요. 쓰는 버전은 설정 `mujuthaek.area.score-version`(지금 `"2026.1"`), 바꾸면 전체 다시 계산.

#### 계산
- `resources/area/calc/life_scores.sql`: 대상 위치(임시 테이블 `target_locations`)의 항목 5개를 SQL 한 번으로. 지표가 없으면(근처에 그 시설이 아예 없음) 그 지표 0점. 실제 자료 3,000곳에서 **0.34초**(15,000줄), 두 번 돌려 다른 줄 0
- 없는 규칙 버전이면 점수를 지우지 않고 오류(설정 실수를 조용히 넘기지 않게)
- `LifeScoreService.recalculate(ids)` / `recalculateAll()` — 세권 지표 뒤에 부름. 이벤트 연결은 공고 연결 PR에서

#### 요청 때 총점 (저장 안 함)
- `TotalScore.of(항목 점수, 가중치 0~10)`: Σ(점수 × 가중치) ÷ 가중치 합, 0~100 정수. 점수가 있는 항목만(직장을 안 넣으면 빠짐), 가중치가 모두 0이면 같은 비중
- **반올림은 `HALF_UP`** — SQL `round()`와 같게. `BigDecimal` 기본처럼 `HALF_EVEN`이면 76.5가 76이 되어 SQL(77)과 달라져요
- `Piecewise`: DB 함수와 같은 직선 잇기(자바). 직장 거리 점수처럼 요청 때 매기는 점수에 씀 (8.4km → 76.5)

### 테스트
- 직선 잇기 경계값: 0·500 → 100, 750 → 85, 1,000 → 70, 1,500 → 55, 2,000 → 40, 2,500 → 20, 3,000·9,999 → 0 (SQL·자바 둘 다)
- 항목 5개 가중치 합 1, 가중치가 걸린 지표는 모두 규칙이 있음
- 손 계산과 비교: 교통 77.5 → 78, 공원 76.5 → 77, 학군 30, 편의 60, 병원(지표 없음) 0
- 같은 입력 두 번 → 같은 점수, FAILED 위치는 점수 없음, 없는 버전이면 오류·이전 점수 유지
- 총점: 76.5 → 77, 74.5 → 75, 직장 빠짐, 가중치 모두 0
