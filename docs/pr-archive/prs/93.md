### 무엇을
3단계(공고 주소 → 좌표)의 마지막, **묶기와 저장**이에요 (3-5). 공고 위치 하나를 받아 좌표를 찾고 `area.notice_locations`에 저장해요.
공고 이벤트(`NoticeLocationsChanged`, [#68](https://github.com/prgrms-be-devcourse/NBE11-13-final-Team02/pull/68))를 받아 이걸 부르는 건 연결 PR이에요.

#### 흐름 (`NoticeLocationService.locate(공고 위치)`)
1. 주소 키 = 주소 정리 결과(`AddressParser`의 정리한 글자)
2. 같은 주소 키로 이미 **정확한 좌표(OK)**가 있으면 그걸 써요 — 검색 API·좌표제공 API 하루 한도를 아끼고, 같은 단지면 좌표가 같게. 대략 위치·실패는 나중에 더 잘 찾을 수 있어서 다시 찾아요
3. 없으면 `AddressLocator`([#91](91.md)·[#92](92.md): 사전 → 검색 API → 좌표제공 API → 대표점) → **경계 검사([#83](83.md))**:
   시군구 경계에서 50m 넘게 밖이면 좌표를 버리고 `FAILED`·`OUT_OF_REGION`, 받은 법정동 경계 밖이면 `region_mismatch`만 표시
4. `notice_locations`에 (공고, notice 위치 ID)로 넣거나 고쳐요. 있던 위치면 area 위치 ID는 그대로라 세권 지표·점수가 계속 가리켜요

- **정답 케이스 끝까지**: 저장소의 실제 법정동코드표를 넣고, 정답 케이스의 정답 주소 ID로 사전을 만들어, 도로명 주소 113개가 주소 정리 → 이름으로 시군구 → 사전으로 모두 정답 주소
