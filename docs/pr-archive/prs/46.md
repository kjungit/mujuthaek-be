### 무엇을
collector가 생활권·상권 원천 파일을 S3 `area/`에 올리고 `area.source.ready`를 보내는 `area-upload` 명령이에요. api([#45](45.md))가 받아 적재해요. (area 적재 스택 4/4, [#45](45.md) 위에 쌓음 — #45의 계약이 먼저 들어가야 해요)

```
uv run python -m mujuthaek_collector area-upload --source BUS_STOP --data-date 2025-10-31 --file 버스정류장.csv
uv run python -m mujuthaek_collector area-upload --source STORES --scope 강원 --data-date 2026-06-30 --file 상가_강원.csv
uv run python -m mujuthaek_collector area-upload --manifest area/area_manifest.csv --skip-upload
```

- `mujuthaek_collector/area/` (새 패키지)
  - `sources.py`: 원천 6종과 S3 키 규칙 `area/{원천}/{기준일}/{영문 이름}.csv`, 상가 시도 ↔ 영문 이름 16개 (전남광주 → `jeonnam_gwangju`). 모르는 원천·시도 없는 상가·ALL이 아닌 시설 범위는 거절
  - `excel.py`: 지하철 엑셀 → UTF-8 CSV (빈 줄 건너뜀, 날짜 `YYYY-MM-DD`, 칸 안 줄바꿈은 따옴표로 유지)
  - `upload.py`: 메타데이터 `source`·`data-date`·`sha256`을 붙여 올리고, 같은 키에 같은 sha256이면 다시 올리지 않음
  - `events.py`: 계약 모양의 봉투, eventId는 `uuid5(NAMESPACE_URL, "https://mujuthaek.kr/events/area.source.ready/{source}/{scope}/{sha256}")`. 아웃박스에 같은 eventId가 있으면 기록하지 않음
  - `command.py`: 파일 하나 / 목록(`--skip-upload`: S3 sha256 메타데이터만 확인하고 이벤트만) + 받을 큐 선언
- `core/file_store.py`: `S3FileStore.put_file`(boto3 `upload_fileobj`, 큰 파일은 multipart), `metadata`. `FileStore` 프로토콜·`MemoryFileStore`에도 추가
- `area/area_manifest.csv`: **2026-10-22에 실제 S3(`area/`)에 올려 둔 원천 21개 목록** (지하철·버스·학교·공원·병원 각 1, 상가 시도 16). `.gitignore`의 `*.csv`에서 이 파일만 예외로 열었어요

### 왜
- 원천 21개는 이미 S3에 있어서, 개발 서버에서는 `area-upload --manifest area/area_manifest.csv --skip-upload`로 적재를 시작하면 돼요. 그 전에 쓰던 `upload_area_files.sh`는 이 명령이 생기기 전 임시용이었어요.
- **받을 큐를 collector가 먼저 만드는 이유**: 발행기는 `mandatory=True`라 받을 큐가 없으면 그 묶음 전체가 되돌려져요. api가 한 번도 뜨지 않은 브로커에서 area 이벤트를 쌓으면 같은 묶음의 공고 이벤트까지 막혀서, 기록하기 전에 api와 같은 설정(`mujuthaek.area.source-ready`, `x-dead-letter-exchange: mujuthaek.dlx`, `.dlq`)으로 큐를 선언해요. extraction이 정책 큐에 한 것과 같은 방식이에요.
- 같은 파일로 두 번 돌려도 S3 업로드·아웃박스 기록·api 적재가 한 번씩만 일어나요.

이번에 안 하는 것: 원천 사이트에서 자동 내려받기(데이터포털·KRIC 내려받기 방식이 제각각이라 다음에), 세권·점수 계산.
