### 무엇을
**출처 규격 (`sources/base.py`)**: 기관별 수집기는 세 가지만 구현해요.
- `list_request(board, page)`: 목록 N페이지 주소(폼 POST면 값, 필요하면 Referer)
- `parse_list(board, body, page_url)`: 목록 → `ListItem`. 목록 표 자체가 없으면 `ParseError`예요. 글이 0개인 것과 구분해요.
- `parse_detail(item, body)`: 상세 → 본문, 항목, 첨부, 상세 화면의 호별 표
- 두 파서는 네트워크를 모르는 순수 함수라, 저장한 화면으로 바로 테스트돼요.

**파이프라인 (`pipeline.py`)**
- 게시판마다 목록 1~5페이지를 봐요.
  - 1페이지 해시가 지난번과 같고 밀린 글이 없으면 바로 끝내요. 새 글이 없으면 게시판당 요청 1번이에요.
- 새 글은 분류해서 처리해요.
  - 모집공고·정정공고: 열어요. 정정공고는 원래 공고에 연결해요.
  - 후속 안내: 원래 공고가 있을 때만 열어요.
  - 나머지와 365일 넘은 글: `SKIPPED`
- 밀린 글(`PENDING`·`FAILED` 3회 미만)과 새 글을 게시판마다 20건까지 처리해요. 남은 글은 다음 회차에 먼저 처리해요.
- 글 처리 순서: 상세 → 공고문 1개(실패하면 두 번째 후보) → 주택목록 → 호별 표 → 해시 비교
  - 해시가 같으면 `DONE`만 바꿔요.
  - 다르면 S3에 올리고, 한 트랜잭션으로 저장하고 이벤트를 남겨요.
- 오류별 처리
  - 차단(403·429·대기실·robots 금지): 그 출처 회차를 `BLOCKED`로 멈추고, 처리 중이던 글은 `PENDING`으로 남겨요.
  - 화면 구조 오류: 그 글만 `FAILED`
  - 첨부 거부: 그 파일만 건너뛰어요.

**실행 명령 (`python -m mujuthaek_collector`)**
- `run`: 스케줄러예요. 평일 9~18시 매시 5분 수집, 매일 3시 정정 확인, 4시 보관 정리, 5초마다 이벤트 발행, `:8091/health`
- 그 밖에 `run-once <출처> [--recheck]`, `run-all`, `relay`, `cleanup`, `save-fixtures <출처>`, `status`
- 발행기(`Relay`)는 `outbox.open_channel`로 채널을 열어요. 확인 모드라서 브로커가 받지 못한 이벤트는 아웃박스에 남고 다음 차례에 다시 보내요 ([#6](6.md)).
- 정기 수집은 `sources.enabled`가 true인 출처만 돌아요. 문제 있는 출처는 DB에서 false로 바꿔 잠시 멈춰요.

**Docker**
- `services/collector/Dockerfile`
  - 빌드 컨텍스트는 저장소 루트예요. platform 라이브러리를 같이 넣어요.
  - `uv sync --frozen`으로 설치하고 일반 사용자로 실행해요.
- `.dockerignore`
- compose `collector` 서비스(apps 프로필): 마이그레이션 완료, RabbitMQ·MinIO healthy를 기다려요. 8091은 localhost에만 열어요.

### 왜
- 기관마다 다른 건 "어떤 주소를 열어 무엇을 꺼내나"뿐이에요. 페이지 넘기기, 멈추는 조건, 분류, 저장, 이벤트는 파이프라인 한 곳에 둬서 9곳이 같은 규칙으로 동작해요.
- Dockerfile에서 고친 것
  - uv 이미지를 lock을 만든 버전(0.12.10)과 맞췄어요.
  - 실행은 `uv run` 대신 가상환경 python을 바로 써요. `uv run`은 컨테이너를 시작할 때마다 패키지를 다시 설치했어요.

### 알아둘 것
- 기관별 파서는 POC에서 확인한 화면 구조를 본뜬 예시로 테스트했어요. **실제 화면 확인은 다음 PR(대전)부터** 출처별로 해요.
- `make up`은 스케줄러를 띄워서 정해진 시간에 실제 기관 사이트에 요청해요.
