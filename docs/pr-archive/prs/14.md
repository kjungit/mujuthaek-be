### 무엇을
AWS 키를 받기 전에, 키가 실수로 저장소에 올라가지 않도록 도구로 막아 뒀어요.

**1. `.gitignore` 보강**
- 원래 `.env`만 있었는데 아래를 추가했어요.
  ```
  *.env
  .env.*
  !.env.example
  *.pem
  *.csv
  .aws/
  ```
- `*.csv`는 AWS 콘솔에서 액세스 키를 내려받으면 `.csv`로 저장되기 때문이에요. 앞으로 테스트용 CSV를 올려야 하면 `git add -f`로 추가해요.
- `infra/.env`, `*.pem`, `.aws/credentials`는 무시되고 `infra/.env.example`은 그대로 올라가는 걸 `git check-ignore`로 확인했어요.

**2. 커밋 직전 키 검사 (`.pre-commit-config.yaml`)**
- 커밋할 때 gitleaks(v8.30.1)가 키·비밀번호처럼 생긴 글자를 찾으면 커밋을 막아요.
- **팀원은 각자 한 번** 설치해 주세요.
  ```bash
  brew install pre-commit    # 또는 pip install pre-commit
  pre-commit install         # 저장소 루트에서
  ```
  처음 커밋할 때 gitleaks를 받느라 몇 분 걸릴 수 있어요.

**3. README 안내**
- "처음 실행"에 `pre-commit install`을 추가했어요.
- AWS 키는 AWS CLI 프로필(`~/.aws/credentials`)에만 두고, 저장소 안의 `.env`·코드·문서에는 넣지 않는다고 적었어요.

**4. GitHub 저장소 설정 (코드 밖, 이미 적용)**
- Settings → Code security에서 **Secret scanning**과 **Push protection**을 켰어요. AWS 키 같은 비밀 값이 든 커밋을 push하면 GitHub가 거부해요.

### 왜
키가 생긴 뒤에 막으면 늦어요. 공개 저장소에 키가 한 번 올라가면 커밋을 지워도 이미 수집됐다고 봐야 하고, 키를 바로 폐기해야 해요. 그래서 로컬 커밋 단계(gitleaks)와 push 단계(GitHub) 두 곳에서 막아요.
