### 왜
개발 서버에 공고·혜택이 안 떠요. 개발엔 수집기가 없고, shovel이 복사하던 수집 원본(raw.*)은 개발 추출이 recorded 모드라 새 공고의 결과를 만들지 못해요.
개발 api가 운영이 만든 결과를 그대로 받게 바꿔요.

### 무엇
1. `shovel.sh`
   - 기본(`--mode results`): 운영 결과 이벤트 `extraction.completed`(공고·창업지원)·`policy.extracted`(혜택)·`area.source.ready`(생활권 원천)
     - api가 받는 이벤트는 이 셋과 `push.subscription.expired`(알림 서버가 회원별로 내는 것이라 제외)뿐이에요. notice 합치기 같은 별도 결과 이벤트는 없어요
   - `--mode raw`: 예전처럼 `raw.notice.collected`·`raw.policy.collected`·`area.source.ready`
   - 다른 모드로 다시 돌리면 그 모드에 없는 바인딩은 풀어요. `--recreate`는 dev.mirror를 지우고 다시 만들어요(쌓인 메시지도 지움)
   - S3: 개발 api가 결과 이벤트로 S3를 읽는 건 `area.source.ready`의 생활권 원천(`area/…`, `S3AreaFileStore`)뿐이에요. 같은 버킷이라 개발 서버 IAM 역할에 읽기 권한이 필요해요. 공고·혜택 결과는 S3를 읽지 않아요(원문은 기관 링크)
2. `copy-prod-to-dev.sh` (운영 서버에서 한 번)
   - 운영 api DB → 개발 `api_dev`: 스키마 notice·benefit·area·eligibility의 테이블. 제외: `notice_reports`·`area_reports`(회원 신고·제보), `criteria_set_history`(관리자 기록). account·notification·chat·traffic·common은 옮기지 않아요
   - 개발 대상 테이블 TRUNCATE … CASCADE → `pg_dump --data-only` 넣기, 한 트랜잭션. 옮기는 테이블끼리의 외래키(공고 `merged_into` 자기 참조 포함)는 넣는 동안 풀었다가 다시 걸어 검증
   - 운영 계정은 `/opt/mujuthaek/.env`(API_DB_URL·USER·PASSWORD), 개발 계정·암호는 입력. 암호는 환경 변수로만 넘겨 명령줄에 안 남아요
   - `--dry-run`: 테이블별 줄 수(200MB 넘으면 추정)·크기·같이 비워지는 개발 테이블만 보여 줘요. `--skip-big`: `address_points`·`stores`(수 GB) 빼기
   - pg_dump·psql은 `postgres:17-alpine` 이미지로 (서버 설치 없음). 배포 워크플로가 서버에서 실행 권한을 줘요
3. README: 「개발 서버 데이터」 절 (옮기는 스키마·테이블 표, shovel 모드 표, 순서)
4. 덤: `deploy.sh` 안내 문구의 `$ENVIRONMENT에는`처럼 한글이 붙은 변수가 bash에서 변수 이름으로 읽혀, 잘못된 서비스 이름일 때 안내 대신 unbound variable로 죽던 것 고침

### 확인
- shellcheck: deploy.sh·shovel.sh·copy-prod-to-dev.sh, actionlint: 워크플로 2개
- shovel.sh를 로컬 RabbitMQ 관리 API에: 기본 → 결과 3개 바인딩, `--mode raw` → 결과 바인딩 2개 풀고 raw로, `--recreate` → 큐 지우고 결과로. 끝나고 큐·계정 지움
- copy-prod-to-dev.sh를 로컬 두 DB(원본 api_fe, 대상 스키마만 복제한 DB)로 (bash 5 컨테이너, 서버와 같은 방식)

### 실행 순서 (머지·배포 뒤)
1. 운영 서버: `./copy-prod-to-dev.sh --dry-run` → `./copy-prod-to-dev.sh`
2. 운영 서버: `./shovel.sh prod --recreate` (이미 raw로 만들었으면) 또는 `./shovel.sh prod`
3. 개발 서버: `./shovel.sh dev`
