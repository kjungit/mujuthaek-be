### 무엇을
로그인 없이 보는 공고 조회 API 4개예요. (REST 스택 4/7, [#49](49.md) 위에 쌓음) 공개됐고(현재 버전 있음) 숨기지 않은 공고만 보여줘요.

| 메서드 | 경로 | 하는 일 |
| --- | --- | --- |
| GET | `/api/v1/notices` | 공개 목록 (필터·정렬·커서) |
| GET | `/api/v1/notices/{id}` | 상세 묶음 |
| GET | `/api/v1/notices/{id}/units?siteId=&cursor=&size=` | 호별 주택목록 |
| GET | `/api/v1/notices/{id}/versions` | 정정 이력 |

- **목록 필터**: `field`(HOUSING 기본 · BUSINESS_SPACE), `regionCodes`(시군구 5자리 또는 시도 2자리), `tenure`(RENT · BUY — 공공·민영 분양이 BUY), `noticeTypes`, `providers`, `statuses`(비우면 마감 제외). 목록 값은 쉼표로 잇거나 여러 번. `sort`: `DEADLINE`(기본, 마감일 없는 공고는 맨 뒤) · `LATEST`(공고일 최신순). 정렬마다 커서가 따로라 정렬을 바꾸면 처음부터
- **목록 한 줄**: `id, field, title, provider, noticeType, regionCode, regionName, status, applyStart, applyEnd, dday, postedOn`
- **상세 묶음** (API 설계 "상세 응답의 묶음"): `header`, `summary`(요약·대상·모집 호수·전용면적 범위), `schedules[]`(지금 단계 `current`), `sites[]`, `unitTypes[]`(주택형별 대상·면적·보증금·월임대료·공급 호수), `conditions[]`(대상별 자격 조건과 근거 원문), `files[]`(기관 링크만), `hasUnits`, `version`, `reviewed`, `updatedAt`
- **주택목록**: 호 단위 공급 묶음의 호·층·주택형·면적·보증금·월임대료·단지와 주소. 없으면 빈 목록
- **정정 이력**: 공개된 버전마다 버전·글 종류·검수 상태·받은 시각과 앞 버전에서 바뀐 항목(`applyEnd`, `summaryText` …)
- 오류: 없거나 숨김·공개 전 → 404 `NOTICE_NOT_FOUND`, 모르는 필터 값·잘못된 지역 코드·UUID 아님 → 400 `VALIDATION_FAILED`, 다른 정렬·손댄 커서 → 400 `INVALID_CURSOR`
- "오늘"은 서울 날짜(`Clock` 빈), 응답 시각은 `+09:00`

### 왜
- 상세·주택목록·이력은 저장해 둔 추출 결과(payload)에서 그때 만들어요. 상세 칸을 테이블로 나누지 않아서 계약이 바뀌어도 저장은 그대로예요.
- 아직 없는 값: 목록의 `depositMinWon`·`rentMinWon`·`tags`·좌표(`lat`·`lng`), 주택목록의 좌표는 area 세권·좌표 계산이 생기면 붙여요. `GET /notices/map`도 그때 만들어요. 맞춤 목록(`POST /notices/search`)과 판정은 다음 PR들이에요.
- `regionName`은 시군구 코드표([#48](48.md))를 채워야 나와요. 비어 있으면 `null`이에요.
- 설계 문서의 목록 필터 `field`가 `HOUSING · BUSINESS`로 적혀 있는데, 이름 기준(백엔드가 기준)에 따라 이벤트 계약과 같은 `BUSINESS_SPACE`를 받아요.
