### 왜
- 지금까지 운영 릴리즈는 모두 Actions에서 손으로 실행(Run workflow)했어요.
- 그런데 태그·릴리즈 노트 단계가 태그 push(`api-v1.2.0`)일 때만 돌아서, **git 태그도 GitHub 릴리즈도 하나도 없어요.** 어떤 버전에 무엇이 나갔는지 남지 않았어요.

### 바꾼 것 (`release.yml` notes job)
- 언제 도나: 배포가 성공했고 **새 버전(빌드 켬)**일 때요.
  - 태그 push든 손으로 실행이든 같아요.
  - 되돌리기(빌드 끔)는 남기지 않아요.
- 태그 이름
  - 태그로 올렸으면 그 태그
  - 손으로 실행했으면 서비스 하나는 `api-v0.2.1`, 전체(all)는 `v0.2.1`
- 손으로 실행하면 배포한 main 커밋(`github.sha`)에 태그를 새로 달고 릴리즈를 만들어요.
  - 노트에는 서비스·버전·실행한 사람·실행 링크와, 이전 릴리즈부터 바뀐 PR 목록(`--generate-notes`)이 들어가요.
- 같은 릴리즈가 이미 있으면(다시 실행) 새로 만들지 않아요.
- 이 워크플로의 `GITHUB_TOKEN`으로 만든 태그는 워크플로를 다시 부르지 않아요. 그래서 태그 때문에 또 배포되지 않아요.
- 슬랙 알림 문구: 빌드 켬이면 「릴리즈 (태그 · 릴리즈 노트를 남겨요)」
- README 「이후 배포 · 롤백」에 손으로 실행하는 방법과 **새 버전은 빌드 켬**을 적었어요.
  - 오늘 `v0.2.1`을 빌드 끔으로 실행해서, 없는 이미지를 받다 실패하고 `v0.1.0`으로 되돌아갔어요.

### 확인

- notes 스크립트를 가짜 `gh`로 실행해 봤어요.
  - 태그 push `api-v0.2.3` → `api-v0.2.3`

  - 손으로 실행 api `v0.2.2` → `api-v0.2.2`
