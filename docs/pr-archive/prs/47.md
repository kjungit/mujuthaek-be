### 무엇을
REST API를 만들기 전에 모든 모듈이 같이 쓸 공통 틀이에요. (REST 스택 1/7, dev에서 시작)

- **오류 응답** (`common/exception`): Problem Details(RFC 9457) + `code`
  - 모양: `type`(`https://mujuthaek.kr/problems/<코드>`), `title`, `status`, `code`, `detail`, `instance`(요청 경로), 입력 검사 실패면 `errors[{ field, reason }]`
  - `ErrorCode`: `VALIDATION_FAILED`·`INVALID_CURSOR`(400), `UNAUTHENTICATED`(401), `FORBIDDEN`·`CSRF_INVALID`(403), `NOT_FOUND`(404), `CONFLICT`(409), `RATE_LIMITED`(429), `INTERNAL_ERROR`(500), `NOTICE_NOT_FOUND`. 기존 `INVALID_REQUEST`는 `VALIDATION_FAILED`로 바꿨어요
  - `errors[]`에는 칸 이름과 어긴 규칙(`Min` → `MIN`, `NotNull` → `NOT_NULL`)만 담고 입력값은 넣지 않아요. 본문을 못 읽음·형식 다름·필수 쿼리 없음도 `VALIDATION_FAILED`, 없는 주소는 `NOT_FOUND`
  - 500은 코드와 시각(`timestamp`)만 보여주고 원인은 로그에만 남겨요
- **커서 목록** (`common/pagination`): `CursorQuery.of(cursor, size, 정렬)` — `size` 기본 20, 1~100. 커서 키를 (정렬 이름, 정렬 값, ID)로 넓혀서, 다른 정렬로 만든 커서나 읽을 수 없는 커서는 400 `INVALID_CURSOR`. 조회는 `fetchSize()`(size + 1)개를 가져와 `CursorPageResponse.from`으로 다음 페이지를 정해요
- **민감 값 가림** (`common/logging/SensitiveFields`): 소득·자산·자동차가액·매출·가용 현금·수급 여부·순위 체크·생년월일 칸의 값을 JSON·record toString 어디서든 `***`로. 500 오류 로그는 메시지와 원인 예외까지 가린 뒤 남겨요
- **이벤트 수신 도우미** (`common/messaging`): `EventEnvelope`, `EventInbox.handleOnce`(봉투 읽기 → `common.processed_events`로 한 번만 처리 → 처리 실패면 기록 안 함, 잘못된 봉투는 재시도 없이 실패 큐), `RabbitTopology`(`mujuthaek.events`·`mujuthaek.dlx`, 큐마다 `.dlq`)
- PostgreSQL 드라이버를 `implementation`으로 (테스트용 `TestDatabase`가 `PGSimpleDataSource`를 써요)
