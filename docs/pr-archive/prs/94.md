### 무엇을
공고와 area를 이어요 (계획의 연결 PR, 38~43번). 지금까지는 notice가 보내는 `NoticeLocationsChanged`를 area가 안 받고 `AreaScoresCalculated`를 아무도 안 보내서, 공고가 들어와도 좌표·점수가 안 생기고 공고 상세 `areaSummaries`가 늘 비어 있었어요.

이제 흐름: notice 공고 반영 → `NoticeLocationsChanged` → (area, 커밋 뒤 비동기) 위치마다 좌표 찾기·저장([#93](93.md)) → 세권 지표([#78](78.md)) → 생활권 점수([#81](81.md)) → `AreaScoresCalculated` → (notice) 공고 상세 `areaSummaries`.

#### `NoticeAreaLinkService` + `NoticeAreaLinkListener`
- 리스너는 notice의 `AreaScoresListener`와 같은 방식: `@Async @TransactionalEventListener(fallbackExecution = true)`. 좌표 찾기가 외부 API를 불러 느려서 공고 반영을 붙잡지 않아요
- **같은 위치는 다시 찾지 않음**: 주소·법정동코드가 그대로면 좌표를 다시 찾지 않고 공고 버전만 올려요(같은 이벤트를 두 번 받아도, 위치 말고 다른 것만 바뀐 새 버전이어도). 지난번이 검색 API 오류(`API_ERROR`)였으면 다시 찾아요
- **바뀐 위치만 다시 계산**: 좌표가 새로 생기거나 바뀐 위치만 지표·점수
- **빠진 위치 지우기**(39번): 이번 목록에 없는 위치는 지워요. 지표·점수는 area 안 외래 키(cascade)로 같이
- **점수 보내기**: 좌표가 있는 위치마다 `LIVING` = 생활권 항목 5개(교통·학군·공원·편의·병원)의 같은 비중 총점(`TotalScore`, 0.5 올림), 규칙 버전 `2026.1`. `COMMERCIAL`은 업종이 있어야 해서(요청 때 계산, 7단계) 보내지 않아요
- **기초 데이터 다시 적재**(42번): 시설·상가를 다시 적재하면(`AreaBaseDataLoaded`) 지표·점수 전체를 다시 계산하고 공고마다 점수를 다시 보내요. 도로명주소·경계 적재는 지표에 안 써서 건너뛰어요
- **실패 목록**(43번): `failedLocations(limit)` — 관리자 API는 2부라 조회 메서드만

#### 저장소
- `PostgresNoticeLocations`: 공고의 위치들(`StoredLocation`), 빠진 위치 지우기, 버전만 올리기, 좌표 있는 위치들, 실패 목록
- `PostgresLocationScores`: 위치별 생활권 항목 점수

### 계획과 달라진 점
- **공고 테이블 외래 키(40번)는 걸지 않았어요**: CLAUDE.md의 "다른 모듈 테이블은 쓰지 않는다·area는 다른 모듈을 부르지 않는다" 규칙 때문(팀 결정). 빠진 위치는 이벤트로 지우고, 공고가 숨김·합쳐짐으로 사라지는 경우는 지금 notice가 위치 이벤트를 안 보내서 그대로 남아요(점수는 notice가 지금 버전 위치만 보여서 화면엔 안 나옴)
- **백필(41번)은 notice 보충 발행으로**: `--notice.backfill=locations`가 위치 이벤트를 다시 보내면 area가 받아요. 좌표 찾기가 외부 API라 `--spring.task.execution.shutdown.await-termination=true`와 넉넉한 `await-termination-period`를 같이 줘야 끝까지 처리해요(리스너 주석에 적음)

### 테스트
- 연결 서비스(실제 DB·진짜 계산기, 검색 API만 가짜): 좌표 찾은 위치만 지표·점수·`LIVING` 점수(notice가 받는 모양: 0~100·시각·규칙 버전), 같은 이벤트 두 번이면 다시 찾거나 계산 안 함, 빠진 위치는 점수와 같이 지움, `API_ERROR` 위치는 다시 찾음, 시설 다시 적재면 다시 계산·다시 보냄, 실패 목록
- **앱 전체**: notice가 계약 예시 공고를 반영하면 area가 비동기로 계산해 공고 상세 `areaSummaries`에 `LIVING` 점수가 나옴
