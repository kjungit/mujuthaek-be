### 무엇을
- `LhSource.make_client`가 `LH_API_KEY`를 읽을 때 `urllib.parse.unquote`로 한 번 풀어서 써요 (`+`가 공백으로 바뀌지 않게 `unquote_plus`가 아니라 `unquote`). 인코딩 안 된 키는 그대로예요.
- LH README, `infra/.env.example` 주석에 "포털에 보이는 키를 그대로 넣어도 된다" 한 줄
- 테스트: 인코딩된 키(`ab%2Bcd%2Fef%3D%3D`)와 원래 키(`ab+cd/ef==`) 모두 같은 값으로 읽히는지

### 왜
- 공공데이터포털 화면에는 인증키가 URL 인코딩된 값(`%2B`, `%3D` 포함, 94자)으로만 보이기도 해요.
- 수집기는 요청할 때 `urlencode`로 키를 다시 인코딩해서, 이 값을 그대로 넣으면 두 번 인코딩돼요. 그래서 LH 분양임대공고문·상세정보·공급정보, 마이홈 모집공고 API 4개가 모두 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`(등록되지 않은 서비스키)를 냈어요.
