### 무엇을
공고 주소(글자)를 좌표로 바꾸는 첫 단계예요. 이미 적재한 전국 도로명주소 사전(`area.address_points`, [#60](60.md))에서 시군구·도로명·지하 여부·건물 번호로 주소를 찾아요.
찾은 좌표는 3-5에서 `area.notice_locations`에 저장되고, 세권 지표([#78](78.md))·생활권 점수([#81](81.md)) 계산에 쓰여요. 사전으로 못 찾는 주소는 다음 단계(검색 API [#82](82.md), 좌표 API)가 맡아요.

#### 찾는 순서 (`PostgresAddressPointLookup.find`)
1. **정확히**: 도로명의 띄어쓰기를 지우고 그대로 (`address_points_name_idx`) → `FILE`
2. **없으면 오타**: 같은 시군구 도로명 목록에서 trigram 유사도 상위 10개 중 **길이가 같고 숫자가 아닌 글자 하나만 다른** 도로명으로 번호까지 같은 주소를 찾아요. 후보 하나에서만 맞을 때만 → `FUZZY`
3. 같은 조건에 주소가 둘 이상이거나 오타 후보 여럿이 맞으면 고르지 않아요. 틀린 좌표보다 못 찾음이 나아요

### 실측 (실제 사전)
정답 케이스(`area/geocode/cases.csv`, [#74](74.md))의 도로명 주소 114개, 그 55개 시군구의 실제 사전 164만 줄로 같은 규칙을 돌렸어요.

| 입력 | 찾음 | 맞는 주소 | 틀린 주소 |
| --- | --- | --- | --- |
| 정답 케이스 그대로 | 113 / 114 (99.1%) | 113 | 0 |
| 첫 글자 오타 하나씩 | 54 / 114 (오타 찾기) | 54 | 0 |
| 끝 글자(대부분 길 번호) 오타 하나씩 | 7 / 114 (오타 찾기) | 7 | 0 |

- 못 찾은 1건은 금천구 시흥대로 377: 사전에 아직 없는 새 건물이라 좌표제공 API(3-3)에서 풀어요
- 처음 규칙(유사도 상위 3개 중 하나만 맞으면)에서는 오타로 찾은 32건 중 3건이 틀렸어요. 「대평들5길」의 번호가 깨진 「대평들가길」이 다른 「대평들○길」의 같은 번지로 갔어요. 숫자만 같게 해도 「노원로10길」 → 「노원로1가길」이 「노원로1길」로 갔어요. 번호가 들어간 길은 번호가 다르면 다른 길이라, 글자 하나 오타만 고치게 했어요
- 세 글자 짧은 이름(「강변로」 → 「가변로」)은 글자 하나만 바뀌어도 유사도가 기준(0.3) 아래라 후보가 되지 않아요. 넓히면 틀릴 위험이 커서 그대로 두고 검색 API(3-2)가 받아요
- 오타가 마침 실제로 있는 다른 길 이름(「공항대로59가길」 → 「59나길」)이 되는 경우는 정확히 맞는 주소라 어떤 규칙으로도 막을 수 없어요

### 계획과 달라진 점
- 이름: 계획의 `AddressPointRepository` 대신 저장소 규칙대로 `PostgresAddressPointLookup`(JDBC 직접, 경계 검사·세권 계산과 같은 방식)
- 오타 후보: 계획은 "유사도 상위 3개 중 하나만 맞으면"이었는데, 실측 결과로 "상위 10개 중 글자 하나 차이만"으로 좁혔어요
- 아직 이 찾기를 부르는 곳은 없어요. 검색 API 연결(3-2 마무리)과 저장(3-5)에서 붙여요
