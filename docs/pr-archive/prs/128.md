### 왜
프론트 사업공간 화면이 전부 목업이에요. 판정 엔진(사업공간 판정 틀 `business-space-judgment.v1`, `MatchQueryService.matchBusinessSpace`)은 있었지만 HTTP로 열린 곳이 없었어요. 1단계로 공간 목록과 공간 하나의 판정을 열어요. 창업지원(사업 지원) 목록과 사업공간 홈 요약은 2단계예요.

### API
#### `POST /api/v1/spaces/search` 맞춤 목록
- 요청: `filters.spaceTypes`(STARTUP_SPACE · SHOP_RENTAL · MEETING_ROOM), `filters.regionCodes`(시도 2자리·시군구 5자리), `applicant`(판정 엔진 입력 `JudgmentApplicantRequest`, 사업 입력은 `business`), `sort`(RECOMMENDED · DEADLINE), `includeIneligible`, `cursor`, `size`
- 응답: `counts`(지원 가능·확인 필요·지원 불가), `typeCounts`(지역만 건 종류별 개수), `items`, `nextCursor`, `hasNext`
- 대상: 열린 사업공간 공고 + 사업공간 모집 정책(K-Startup·기업마당 입주기업 모집, `policy=true`, 상세 없이 `detailUrl` 원문)
  - 공고면 공고 목록 정보(기관·종류·지역 이름·세권 태그)를 붙여요
  - 모집 정책은 종류가 없어서 STARTUP_SPACE, 접수 상태는 기간으로 정해요
- 정렬: 지원 가능 → 확인 필요 → 지원 불가, 같으면 마감 임박
- 출처 `source`(KSTARTUP · BIZINFO, 원문 주소로), 같은 모집이 두 출처에 있으면 이름(글자·숫자)이 같은 것 중 하나만 (공고 → K-Startup → 기업마당 순으로 남김)

#### `POST /api/v1/spaces/{id}/evaluate` 공간 하나의 판정
- 응답: `id`, `policy`, `source`, `title`, `detailUrl`, `applyStart`·`applyEnd`·`dday`·`status`, `regionCodes`, `judgment`(판정 결과, 판정 틀이 없으면 null)
  - 모집 정책은 공고 상세가 없어서 프론트가 이 응답으로 간단한 상세를 보여줘요
- 열린 사업공간이 아니면 404 `NOTICE_NOT_FOUND`
- 상세 내용은 공고 상세 `GET /notices/{id}`를 그대로 써요

### 바뀐 점
- `MatchQueryService`: `judgeBusinessSpaceAll`(지원 불가까지), `judgeBusinessSpace(id)` 추가. 기존 목록 판정은 같은 흐름을 써요
- `SpaceSearchService`, `SpaceController`, 요청·응답 DTO
- 테스트: `SpaceSearchServiceTest`(지역 거르기·정책 접수 상태·정렬), `MatchQueryServiceTest`에 공간 목록·하나 판정

### 남은 것
- 지금 수집·추출 흐름에서는 사업공간이 공고로 들어오지 않고 모집 정책(판정 틀)으로만 들어와요 (추출이 사업공간 공고를 아직 지원하지 않음)
- 출생 연월만 보내는 프론트 방식과 달리 판정 엔진은 생년월일을 받아서, 프론트는 아직 나이를 보내지 않아요
