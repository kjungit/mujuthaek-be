### 왜
dev 프론트(Vercel)에서 구글 로그인을 시작하면 Google이 "OAuth 2.0 policy … secure response handling / invalid_request"로 거절해요.
api가 redirect_uri를 요청 주소(`{baseUrl}`)로 만드는데, Vercel rewrites → nginx → api를 거치면 Vercel이 원래 주소(X-Forwarded-Host·Proto)를 넘기지 않아 `http://<서버 IP>/login/oauth2/code/…`가 돼요.

### 무엇
1. kakao·naver·google redirect-uri = `${OAUTH_REDIRECT_BASE_URL:{baseUrl}}/login/oauth2/code/{registrationId}`. 값이 없으면 지금처럼 요청 주소(로컬 개발 그대로)
2. 로그인 성공·실패·탈퇴 뒤 프론트로 보내는 주소는 이미 `FRONTEND_URL`을 써요 (`LoginSuccessHandler`·`LoginFailureHandler`, 바꾸지 않음)
3. nginx: 들어온 X-Forwarded-Proto가 없으면 https로 넘겨요 (이 서버로 들어오는 길은 Vercel뿐). Host·For는 그대로
4. README(infra/deploy·api)의 ENV_FILE 목록에 `OAUTH_REDIRECT_BASE_URL` (운영 https://mujuthaek-fe.vercel.app, 개발은 dev 프론트 주소)

[#163](https://github.com/prgrms-be-devcourse/NBE11-13-final-Team02/pull/163)(운영 프로필에서 FRONTEND_URL로 고정)을 이 PR로 대체해요.

### 확인
- 새 테스트 `OAuthRedirectBaseUrlTest`: `OAUTH_REDIRECT_BASE_URL=https://example.vercel.app`이면 `/oauth2/authorization/google`(kakao·naver도)의 Location에 `redirect_uri=https://example.vercel.app/login/oauth2/code/google`. 값이 없을 때(요청 주소)는 기존 `SecurityIntegrationTest`(30개) 그대로 통과
- 인가 요청(state) 저장소: 스프링 기본(세션, `JSESSIONID`). 세션 정책이 STATELESS여도 이 저장소는 세션을 만들어요. 쿠키는 `Path=/; HttpOnly`, Domain 없음(그 주소 전용), SameSite 표기 없음(브라우저가 Lax로 봄) → Vercel 주소에 저장되고, Google에서 돌아오는 최상위 GET 이동에 실려요
- api 이미지(prod 프로필) + nginx로 실제 흐름: 시작 → redirect_uri가 `https://example.vercel.app/…`, 세션 쿠키·state를 들고 콜백 → state를 찾아 Google 토큰 교환까지 감(더미 client라 `invalid_token_response`), 쿠키 없이 콜백 → `authorization_request_not_found`. 실패 뒤 `FRONTEND_URL/login?error=social&reason=…`

### 사람이 할 일
- ENV_FILE에 `OAUTH_REDIRECT_BASE_URL` (운영·개발 각 프론트 주소), `FRONTEND_URL`도 같은 주소인지 확인
- 소셜 로그인 콘솔 3곳에 `<그 주소>/login/oauth2/code/{kakao,naver,google}` 등록
